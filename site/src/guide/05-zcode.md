# ZCode 中国版体验

> 本机版本：3.7.6；实测 2026-08-12；订阅核验 2026-08-11
>
> 测试条件：BYOK（OpenCode Go / DeepSeek V4 Flash / 最高推理 / 变更前确认）。5 分 41 秒是上述组合共同作用的结果，不能单独归因于 ZCode 或 DeepSeek；BYOK 成本未知，不与托管 Credits 比较。

## 1. 一句话结论

**变更透明性最强的产品**：审查视图提供逐文件增删统计（+46、+37、+84 等），每一份输入/输出/验收文件的改动都可逐项核对，Git 与任务管理深度整合。代价是门槛：需要理解模型/API/推理强度概念，新手要先跨过配置门槛。

## 2. 关键事实

- **产品与版本**：ZCode 中国版（窗口与产品名均显示 `ZCode`），3.7.6
- **地区与计费**：中国区账号；官方套餐积分计费，BYOK 由外部供应商结算
- **入门分组**：代码优先型 Agent（国内）；建议基础：编程或系统配置经验（新手门槛较高）
- **运行方式**：混合（官方积分路径或 BYOK）；自主程度：中—高（变更前确认可人工把关）
- **官方更新日志**：zcode.z.ai/cn/changelog；本机 3.7.6 与官方最新一致（08-12：PPT 逐元素评论等）；3.7.5 记忆页按项目浏览、任务工作台分组（08-10）

## 4. 核心能力

- **已验证**：6 份 Markdown 一次生成；任务汇报（交付说明 + 未解决问题清单）、审查视图（文件+路径+增删行数+内容预览）、权限模式（变更前确认，写入需人工批准）；未发现读取 input 之外文件
- **入口可见未实测**：自动化、技能、终端、闲时任务模板
- **新手路径**：新建任务 → 选运行目录 → 配置模型渠道与推理强度 → 设权限 → 粘贴提示词 → 发送 → 逐次批准写入

## 5. 实测记录（共同基准任务）

- **结果**：6/6 交付一次完成，7/7 输入 SHA-256 与基线一致；总用时 5 分 41 秒；权限确认与人工回复各 ≥1 次（变更前确认模式）
- **亮点**：材料边界处理较好（明确声明目录是重建提案）；写作计划 P0-P2、依赖链、阻塞项完整；待办九组复选框分层清楚
- **问题**：**自检漏列第 7 个输入文件** `OUTPUT-REQUIREMENTS.md`，且未反映真实权限确认过程——只看自检会低估实际介入
- **边界**：3.7.6 未观察到统一 Auto 模式，新手需自行选择模型渠道；优势任务（代码项目）、边界任务（Provider 不可用/余额耗尽恢复）待 benchmark v2 统一测试

## 7. 适合与不适合

**适合**：需要 Git 级变更透明的代码用户（逐文件增删统计可逐项核对）；愿意配置模型与 API、重视写入可控性的用户；有编程或系统配置经验的用户。

**不适合**：零基础新手（模型/API/推理概念门槛高）；想要「打开就用」托管体验的用户（无统一 Auto 模式）；希望客户端内直接看到成本费用的用户（BYOK 成本需另查供应商账单）。

## 8. 最终结论

- **有条件推荐**：有配置基础者可先体验 5 天新手额度；纯零基础建议先读第 1 章（模型是什么）、第 4 章「自带模型（BYOK）」小节和附录 A 术语表的「模型」「API Key」条目，再决定是否尝试
- **定位**：**代码/项目型主 Agent 候选**（变更透明性最高）；代码任务量大且需要完整变更审阅时，GLM Coding Plan 按档位选择
- **与相邻产品差异**：与 Qoder 同属代码优先型——ZCode 是 BYOK 路径（变更统计最细、写入需批准），Qoder 是托管 Auto 路径（最快最省但边界失分）；与 Codex 相比变更统计更细但配置门槛更高，Codex 托管订阅开箱即用
- **待核验**：统一 Auto 模式是否提供、精确权限确认次数、代码优势任务、外部成本核算
