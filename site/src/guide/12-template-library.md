# 第 12 章：建立自己的模板库

## 本章解决什么问题

同一类任务做了三遍，每次都要重新打字解释，烦。**模板就是把「重复的部分」固化下来，只留「每次变化的部分」填空。** 本章教你建三类模板（任务、检查清单、输出格式），并警告一个误区：**模板不是万能提示词**。产出：三个个人常用任务模板。

## 从一个真实场景开始

对比两次写「周报」：

**每次重打**：打开 Agent，重新输入「帮我写周报，我这周做了……（200 字），格式要……」，每次理解的格式都略有不同，还得反复修。

**用模板**：`weekly-report.md` 固定结构——本周完成/下周计划/风险与求助/数据口径；你只填「本周 3 件事 + 1 个风险」，发一句「用 weekly-report 模板整理我的周报」，10 分钟搞定，格式永远一致。

**模板的本质：把「判断」从每次重复里抽出来，存成一次性的资产。**

## 先说结论

1. **四类可模板化内容**：任务卡（怎么描述）、检查清单（怎么验收）、输出格式（长什么样）、案例（怎么处理同类问题）；
2. **模板 = 固定结构 + 变量占位**：结构写好后稳定，变量每次填；
3. **判断标准**：做第三遍时，想想「哪部分是重复的？」重复的 → 模板；不重复的 → 变量；
4. **模板不是万能提示词**：万能提示词是「一句话期望全懂」，模板是「结构化工作单」——后者才稳定可复用；
5. **模板要版本迭代**：每次使用后标记「哪里不适用」，改一版，别怕改。

## 必要概念

- **模板（Template）**：带变量占位的结构化文档（填空题试卷，题目固定，答案每次不同）。
- **变量（Variable）**：模板中每次需要填写的部分，用占位符标出（如 `【本周完成】`）。
- **版本（Version）**：模板的迭代记录，至少保留「当前版」与「上次改了什么」。
- **适用范围（Scope）**：模板适用/不适用的任务类型，写清楚避免硬套。

## 四类模板与写法

| 模板类型 | 固定什么 | 变量什么 | 例子 |
|---|---|---|---|
| **任务卡模板** | 六要素结构 + 你的常用口径 | 目标、材料、验收点 | 第 7 章任务卡 + 你的固定禁区 |
| **检查清单模板** | 验收项、常见错误 | 具体数字、文件 | 第 10 章验收清单 |
| **输出格式模板** | 标题层级、表格列、风格 | 内容 | 周报、会议纪要、对比表 |
| **案例模板** | 背景/任务/过程/验收结构 | 内容 | 第 6 篇案例结构 |

## 跟着做：创建你的前三个模板

### 第一步：盘点你的高频任务

从序章任务 + 最近一个月做过的事里，找出 3 个重复 ≥2 次的类型（如：整理材料、写总结、做对比）。

### 第二步：抽「重复部分」

对每个类型，回答：每次说一样的是什么？（结构、口径、禁区、格式）每次在变的是什么？（具体内容）。

### 第三步：写模板文件

用 `【变量】` 标出变量，固定部分写清楚。示例（输出格式模板）：

```markdown
# 【标题】

> 生成日期：【日期】｜数据核验：【核验日期】｜来源：【材料路径】

## 结论（先给结论）
【一句话结论】

## 对比
| 维度 | 【项A】 | 【项B】 | 说明 |
|---|---|---|---|
| 【维度1】 | | | |

## 来源与限制
【材料清单 + 哪些未验证】
```

### 第四步：试用并迭代

用模板跑一次真实任务，把「不适用」「没说清」的地方改掉，版本号 +1，写「本次改动」。

## 一个完整示例

本书的模板库（`templates/` 目录）就是范例：

- `chapter-template.md`（章节模板）：固定「本章解决什么问题 → 真实场景 → 结论 → 概念 → 跟着做 → 示例 → 常见错误 → 安全提醒 → 练习 → 成果 → 小结」，变量是每章主题——你正在读的每一章都按它生成；
- `case-study-template.md`（案例模板）：固定案例结构（摘要→背景→需求→判断→任务卡→过程→问题→修正→验收→复盘→最小版本）；
- `agent-review-template.md`（产品体验模板）：十段式结构（一句话结论→版本地区→…→最终结论）。

**这些模板让 20 多个章节结构统一**——读者在任何一章都知道去哪找「常见错误」或「安全提醒」：一致性 + 可预期。

## 常见错误与恢复方法

| 现象 | 可能原因 | 怎样修正 |
|---|---|---|
| 模板越写越长，最后没人用 | 想把所有情况都装进去 | 砍到 80% 场景够用，极端写进适用范围 |
| 硬套不合适的模板 | 没写适用范围 | 头部加「适用/不适用」 |
| 模板像万能提示词 | 变量没标清 | 变量用 `【】` 标出，固定部分写「命令式」 |
| 改来改去没有记录 | 没版本管理 | 文件内加版本注释：v1.2 改了什么 |
| 模板成了僵化教条 | 过度模板化 | 记住：模板服务任务，任务不服务模板 |

## 安全提醒

- 模板里不要写死敏感信息（密码、账号），涉及时用变量占位「【提供于任务时】」；
- 任务卡模板里的禁区条款是**默认安全配置**，别为省事删掉；
- 模板被多人/多项目共享时，先确认里面的口径适用于新场景。

## 本章练习

30 分钟：按「跟着做」完成你的前三个模板（建议：任务卡、验收清单、最常用输出格式），各跑一次试用并写版本记录。

## 你应该带走的成果

- **三个个人常用任务模板**（任务卡 + 验收清单 + 输出格式），含变量标注与版本记录。

## 本章小结

1. 做第三遍时，停下来抽重复部分——那是模板的原料；
2. 四类模板：任务、检查清单、输出格式、案例；
3. 模板 = 固定结构 + 变量占位，不是万能提示词；
4. 写清适用范围，版本迭代；
5. 模板是通往 Skill 的下一级台阶（第 13 章）。
