# 2. 新手决策路径

> 目标：从「不知道装哪款」走到「先试用 1–2 款」
>
> 方法：四步过滤，每步只回答一个问题。全程不需要理解模型参数。

## 第 1 步：硬约束过滤（先排除「不能用的」）

回答四个问题，任一为「否」即排除该产品：

| 问题 | 排除条件举例 |
|---|---|
| 官方服务覆盖我的地区吗？ | 海外产品在中国大陆不可用/不稳定 |
| 我能注册、登录、付费吗？ | 无对应支付方式、注册受限 |
| 我的资料允许交给它处理吗？ | 公司/组织禁止上传，或我对隐私敏感 |
| 账号中断我能承受吗？ | 订阅中断意味着能力+历史同时不可用（Claude 阻断案例） |

> **Claude 特别提醒**：作者在教程写作期间账号被封，能力无法进入统一任务。如果你对 Claude 感兴趣，第 1 步就是做账号可用性检查；**能力判断和账号稳定性判断必须分开**。

**这一步通常已经能排除 2–3 款。** 例如：不能接受资料出境的读者直接排除海外托管产品（Claude、Codex）；不想配置 API 的读者排除 BYOK 产品（ZCode、Hermes）。

## 第 2 步：按任务类型选起点

| 我的主要任务 | 第一梯队（先试用） | 对照梯队（备选） |
|---|---|---|
| 中文办公、文档、日常任务，零基础 | **TraeWork CN、WorkBuddy** | QoderWork（扩展样本，未正式纳入） |
| 代码项目为主，能接受 IDE | **Qoder CN、ZCode CN** | Codex |
| 工作+代码+设计综合交付，已有订阅 | **Codex** | WorkBuddy、TraeWork |
| 高自主、模型自由、自托管 | **Hermes Desktop** | ZCode |

判断依据（来自 2026-08-12 实测）：

- 办公零基础：TraeWork 与 WorkBuddy 都是 0 人工介入、无需配置模型；TraeWork 三模式直观，WorkBuddy 变更可见性更好（+647/-0 diff）——两款都值得试，二选一靠第 3 步；
- 代码优先：Qoder 最快最省（2:00/¥0.25）但存在越权读取，ZCode 变更透明最强但要配置模型；Codex 是托管路径里综合一致性最佳、审阅支持提交推送；
- 极客路线：Hermes 是唯一有真实自动恢复实证的产品，四视图最灵活；代价是 Provider/API/环境配置与维护责任都在自己身上。

## 第 3 步：用偏好卡出胜负

在第 2 步的第一梯队内，回答三组偏好问题：

| 偏好问题 | 答案倾向 | 指向 |
|---|---|---|
| 成本要在客户端直接可见吗？ | 要 | Qoder（展示人民币）、TraeWork/WorkBuddy（展示积分/Credits） |
| 数据边界敏感吗？「无弹窗」能接受吗？ | 非常敏感 | Codex、ZCode、TraeWork、WorkBuddy（本轮未越权） |
| 变更要逐文件核对吗？ | 要 | ZCode（增删统计最细）、Codex、WorkBuddy |
| 接受学习配置吗？ | 不接受 | 托管路径；排除 BYOK |
| 要「审阅后直接提交推送」吗？ | 要 | Codex（实测支持） |

如果第一梯队两款仍然分不出，就都试用（第 4 步用真实任务定胜负）。

## 第 4 步：用真实任务试用并记录

复制「个人选择卡」（仓库里的 `docs/10-selection-matrix.md` 第 4 节；该文件是仓库内部底稿，站内打不开——卡片内容其实就是三行：**硬约束过滤后的候选清单 + 按任务类型圈的 1–2 款 + 偏好卡打分**，你可以直接照着这三行在纸上画一张），然后用**你自己的真实任务**复测，不要用演示任务：

1. **选 1 个真实小任务**（15–30 分钟能完成，如整理一份周报素材）；
2. 逐款完成，记录：总用时、人工介入次数、权限弹窗次数、产物是否一次通过、**你是否看得懂它改了什么**；
3. 用下面的「试用记录表」固定证据，7 天后回来对比再决定是否付费。

| 记录项 | 产品 A | 产品 B |
|---|---|---|
| 产品与版本 / 模式与模型 | | |
| 任务名称 | | |
| 总用时 | | |
| 人工介入次数及原因 | | |
| 权限确认次数 | | |
| 产物是否一次通过 | | |
| 变更/差异是否看得懂 | | |
| 本轮消耗（单位写清楚） | | |
| 我能否独立恢复失败 | | |

> 成本记录务必写单位：`Credits`、`积分`、`¥`、`API 账单`——它们不可互相换算，只和自己比。

## 决策路径总览（一图流）

```
第1步 硬约束过滤 ──排除：地区/账号/支付/合规不可用者（含 Claude 先做可用性检查）
   │
   ▼
第2步 按任务类型 ──办公→TraeWork/WorkBuddy｜代码→Qoder/ZCode/Codex｜综合→Codex｜极客→Hermes
   │
   ▼
第3步 偏好定胜负 ──成本可见/边界敏感/变更核对/拒绝配置/审阅提交 各取所需
   │
   ▼
第4步 真实任务试用 ──记录六项指标 → 7 天后对比 → 决定是否付费
```

## 常见错误与恢复方法

| 现象 | 可能原因 | 怎样修正 |
|---|---|---|
| 用了两天发现「好像不如别人说的好」 | 用演示任务或别人的任务测的 | 换成自己的真实任务重测 |
| 两款都挺好，不知道选哪个 | 缺少固定记录 | 用试用记录表逐项打分，不要凭感觉 |
| 看总分选了「第一名」 | 误信了不存在的排名 | 回到 1.6：四种成本单位、两种路径、单一任务集，任何总分都不可比 |
| 换模型/换配置后体验大变 | 把 BYOK 结果当成了产品能力 | 对照 1.3 测试条件，确认你复现的是同一条路径 |
| Claude 账号被封后不知所措 | 没做第 1 步可用性检查 | 先查地区/账号/支付，再决定是否投入 |
