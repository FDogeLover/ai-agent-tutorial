# 第 22 章：软件与项目搭建案例——从零到可发布的教程仓库

## 案例摘要

- 使用场景：软件与项目搭建
- 使用者基础：能完成第 7–18 章学习（不要求编程，但要求按步骤操作）
- 使用的 Agent：桌面 Agent（Codex 等，本项目实际使用） + 视觉模型辅助
- 完成时间：约两周（跨多个阶段）
- 风险等级：中（涉及 git、版本控制、发布）
- 最终交付物：公开 GitHub 仓库（23 章教程 + 实测数据 + 截图 + 文档）

## 任务背景

教程内容规划好后（第 21 章），需要一个「能放内容、能协作、能发布」的项目仓库，并把「七款产品实测」这个研究任务也纳入项目管理——实测数据要归档、截图要规范、结论要可回查。这是一个典型的软件项目搭建任务：**内容工程 + 数据归档 + 版本管理**。

## 原始需求

> 「建一个教程仓库，把章节、素材、实测数据都放进去，并且能管理好版本。」

## 任务判断

- 为什么适合 Agent：目录/文件操作、批量整理、数据汇总、重复性文档工作；
- 交给 Agent：建目录骨架、批量格式化、基准测试执行、界面文档撰写、评分数据整理；
- 人必须做的：架构决策（章节结构）、验收（每阶段）、git 关键操作确认、发布决策。

## 整理后的任务卡（阶段一：框架搭建）

- **目标**：建立 23 章教程的仓库骨架；
- **上下文**：面向零基础读者；中国版产品只用中国站资料；
- **输入材料**：教程规划文档（`docs/00-06`）；
- **范围与约束**：只创建新文件，不删除既有内容；目录按规划命名；
- **交付物**：仓库结构 + README + docs/ 系列规范文档；
- **验收标准**：目录与规划一致；每份规范文档有明确职责；无内容缺失。

## 执行过程（六个阶段）

1. **框架搭建**：建仓库、23 章目录、规范文档（`docs/00-06`）、模板（`templates/`）；
2. **定价调研**：核对七款产品中国版价格与福利，产出 `docs/07`（易变信息集中管理）；
3. **本机界面核对**：安装版本、界面形态记录（`docs/09`）；
4. **基准实测**：设计统一任务（`docs/08`）→ 七款产品实测 → 数据归档（`research/runs/`）；
5. **截图与界面讲解**：18 张截图 → 视觉模型分析 → 7 份界面讲解文档（`docs/11-interface-guides/`）；
6. **评分与正文**：六维评分（`docs/12`）→ 产品页（第 5 章）→ 选择矩阵（`docs/10`）→ 第 6 章。

## 出现的问题（真实记录）

- **git 状态被干扰**：开发环境后台的 Git 集成反复重置本地分支引用，常规提交失败 → 改用「提交哈希直推」方式绕过（提交对象始终安全）；
- **工作区文件被清理**：8 个文档从工作区消失 → 从 git 恢复（教训：内容在版本库里就是「后悔药」）；
- **提交树不完整**：一次构建的提交缺失大量文件 → 用差异校验发现并重建（第 18 章回归验证的实战）；
- **截图命名不统一**：早期草稿与规范冲突 → 统一命名规范并更新；
- **文档链接失效**：章节间引用路径错误 → 批量链接校验脚本修复。

## 修正与判断

- 版本管理策略：**所有内容先入 git 再继续**，任何阶段可回滚（可恢复设计，第 8 章）；
- 证据归档：实测数据、截图、运行记录全部入库，评分结论必须可回查（可信度机制）；
- 易变信息：价格/版本统一在 `docs/07` 维护，正文引用不复制（更新机制）；
- 发布流程：成块合并（squash PR），main 保持可发布状态。

## 最终结果与验收

- 公开仓库：`FDogeLover/ai-agent-tutorial`（GitHub）；
- 内容：23 章目录 + 5、6 章完整正文 + 其余章节正文 + 实测数据 + 18 张截图 + 7 份界面文档 + 规范文档；
- 验收：每阶段按任务卡验收；发布前批量校验链接与事实分级。

## 复盘

- Agent 做得好的：骨架搭建、批量整理、基准执行、界面文档、评分数据整理；
- 人必须介入的：架构决策、每阶段验收、git 异常处置、发布决策；
- 可沉淀：**项目规则集**（`docs/03` 编辑规范 + `docs/04` 内容清单 + 链接校验脚本）——即第 16 章 Harness 六层架构的完整落地案例；
- 教训：项目类任务中，**版本管理与备份不是可选项，是安全底线**（第 8 章「后悔药」）。

## 给新手的最小版本

40 分钟复现：为一个个人项目（哪怕是「家庭菜谱库」）建仓库：建目录 → 写 3 条项目规则 → 加 1 个模板 → 用 Agent 生成 2 份文档 → 提交并验证「删了能恢复」。**项目搭建的关键不是代码，而是「规则 + 版本 + 验证」三条线。**
