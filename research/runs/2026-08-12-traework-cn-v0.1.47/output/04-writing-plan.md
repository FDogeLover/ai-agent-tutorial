# 写作计划

写作计划按五个阶段组织，每个阶段标注优先级（P0 最高，P3 最低）、前置依赖和阻塞条件。阶段内的章节可以并行推进，阶段之间通常存在依赖关系。

## 优先级说明

- **P0**：教程的地基，不做则后续章节无法定位。本任务已完成。
- **P1**：读者入门的核心路径，决定读者是否能迈出第一步。
- **P2**：进阶内容和横向对比，构成教程的差异化价值。
- **P3**：参考性内容，可与其他阶段并行编写，不阻塞主线。

## 阶段二：读者入门路径（P1）

目标：让读者读完前五章后，能独立安装一款产品、完成一个真实任务、看懂 Agent 的操作和风险。

### 可立即开始的章节

| 章节 | 内容 | 前置依赖 | 预计阻塞 |
|------|------|----------|----------|
| 第 1 章 | 教程适合谁、能做什么、读法指引 | 无 | 无 |
| 第 2 章 | 七款产品四类分组、选择思路 | 无 | 分组标准需作者确认（D8） |
| 第 5.4 节 | 如何确认 Agent 修改代码后没有改坏 | 无 | 无 |
| 第 14 章 | 术语对照 | 无 | 无 |

### 需要产品访问权限的章节

| 章节 | 内容 | 前置依赖 | 阻塞条件 |
|------|------|----------|----------|
| 第 3 章 | 安装与登录（七款产品分节） | 各产品可登录的账号 | Claude 账号被封（D6）；Codex 身份待确认（D7） |
| 第 4 章 | 用 Agent 完成真实任务 | 第 3 章；选定第一款演示产品 | 作者需决定第一篇案例类型（D2） |
| 第 5 章 | 看懂 Agent 做了什么 | 第 4 章；正式截图 | 截图规范需先确定（见第 5.1 节要求） |

### 阻塞项与建议

- **D2（第一篇案例类型）**阻塞第 4 章核心内容。建议作者优先决定，因为第 6-9 章的进阶案例也在此基础上展开。
- **D6（Claude 账号）**和 **D7（Codex 身份）**阻塞对应产品的第 3 章分节。建议先写其余五款产品的安装登录，Claude 和 Codex 部分标注"待确认"。
- **截图规范**：笔记要求截图解释入口、操作、结果或风险。建议在写第 3 章之前先确定截图标注模板（箭头、编号、说明文字的位置和格式）。

## 阶段三：进阶工作流（P2）

目标：从单次任务过渡到稳定可复用的工作流，通过真实失败案例讲解模板、Skill 和 Harness。

### 依赖关系

```
第 4 章（第一个任务）
  └─→ 第 6 章（模板）
        └─→ 第 7 章（Skill）
              └─→ 第 8 章（Harness）
                    └─→ 第 9 章（多 Agent 协作）
```

| 章节 | 内容 | 前置依赖 | 阻塞条件 |
|------|------|----------|----------|
| 第 6 章 | 模板：让 Agent 稳定重复执行 | 第 4 章完成 | 无 |
| 第 7 章 | Skill：扩展 Agent 能力 | 第 6 章完成 | 需要一个真实 Skill 设计案例，包含失败和调整过程 |
| 第 8 章 | Harness：当 Agent 出错时 | 第 7 章完成 | 需要一次真实的任务失败和恢复案例 |
| 第 9 章 | 多 Agent 协作 | 第 8 章完成 | 需要一个多 Agent 协作的实际场景 |

### 关键说明

- 第 7 章和第 8 章是教程差异化的核心。读者反馈（模拟）中明确提到"最好能看到第一次设计为什么失败，以及后来怎样调整"。这两章不能用最终成果倒推写法，需要记录真实的设计-失败-调整过程。
- 第 8 章的 Harness 案例需要一次"自然发生"的任务失败，而非人为构造。建议在日常使用 Agent 时留意并记录。

## 阶段四：横向对比（P2）

目标：在七款产品上执行统一任务，给出有依据的横向对比结论。

### 依赖关系

```
第 3 章（安装登录，七款产品全部完成）
  └─→ 第 10 章（统一任务实测）
        └─→ 第 11 章（价格与稳定性）
              └─→ 第 12 章（按场景推荐）
```

| 章节 | 内容 | 前置依赖 | 阻塞条件 |
|------|------|----------|----------|
| 第 10 章 | 七款产品统一任务实测 | 七款产品均可登录操作 | Claude 账号（D6）、Codex 身份（D7） |
| 第 11 章 | 价格、Credits 与账号稳定性 | 各产品定价信息核实完成 | Credits 与活动规则需复核（TraeWork、WorkBuddy） |
| 第 12 章 | 按场景选择产品 | 第 10、11 章完成 | 无 |

### 关键说明

- 第 10 章是整个教程工作量最大的章节，需要在七款产品上逐一执行共同基准任务并记录结果。建议按产品分组（海外、国内、代码、开源）逐批推进。
- 第 11 章的定价信息属于高变动类别，建议集中维护并在每段信息后标注核对日期。
- 第 12 章遵循"不做总排名"原则，按场景给出推荐而非综合排名。

---

## 阶段五：参考与保障（P3）

目标：提供安全操作指引、术语对照和申诉方案，作为读者随时查阅的参考。

| 章节 | 内容 | 前置依赖 | 可并行性 |
|------|------|----------|----------|
| 第 13 章 | 安全操作指南 | 无 | 可与阶段二、三并行 |
| 第 14 章 | 术语对照 | 无 | 可与阶段二、三并行 |
| 第 15 章 | 账号申诉与替代方案 | 各产品申诉渠道信息 | 部分依赖第 10、11 章的实测结论 |

### 关键说明

- 第 13 章的安全操作分级（安全、需确认、禁止）可以从前三章的实际操作中逐步积累，建议边写边补充。
- 第 15 章的申诉渠道需要各产品官方信息，目前材料中仅有 Claude 账号被封的案例，其余产品的申诉流程待补充。

## 建议推进顺序

1. 作者确认 D2、D8、D9 → 解锁阶段二核心内容
2. 编写第 1、2、14 章（不依赖产品访问）+ 第 13 章初稿
3. 确定截图规范，编写第 3 章（先写可登录的五款产品）
4. 编写第 4、5 章（选定产品后逐步推进）
5. 阶段二初稿完成后，作者确认 D1 → 确定首批发布章节
6. 并行推进阶段三（第 6-9 章）和阶段五（第 13-15 章）
7. 七款产品均可访问后，推进阶段四（第 10-12 章）
8. 全部章节完成后，作者确认 D3、D5 → 部署发布
