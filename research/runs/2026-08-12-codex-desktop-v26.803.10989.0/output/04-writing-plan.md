# 结构化写作计划

> 优先级：P0 = 阻塞首稿或事实安全；P1 = 构成首发价值；P2 = 可在核心闭环后推进。  
> 所有产品事实均须带日期、地区、产品线和来源类型。

## 1. 阶段与依赖

| 阶段 | 优先级 | 主要工作 | 前置依赖 | 产出 / 完成标准 |
|---|---:|---|---|---|
| W0 决策冻结 | P0 | 确定第一批章节、第一篇案例、比较维度；指定易变事实复核责任 | 无 | D-01、D-02、D-07、D-08 有明确结论；未决项仍清楚标“待确认” |
| W1 证据与规范 | P0 | 建立事实记录表、截图规范、术语口径、风险动作清单、统一验收模板 | W0 可并行启动；案例细节依赖 D-02 | 每条事实可追溯；截图有日期/入口/说明/替代文字；高风险动作有人工检查点 |
| W2 基础章节首稿 | P0 | 写导读及第 1—4 章，解释 Agent、工作区、进度、权限、验证和选型方法 | W0、W1 的术语与风险口径 | 零基础读者无需 CLI 即可理解；模拟反馈中的核心疑问均有对应位置 |
| W3 首个完整案例 | P0 | 写第 9—11 章：准备、执行、检查、失败与恢复 | D-02；W1；至少一款产品可稳定使用 | 一个低风险、可重复、可验证的小任务形成闭环；所有权限动作可见 |
| W4 产品事实卡 | P1 | 补齐七款产品的版本、地区、账号、界面、成本与限制 | W1；可与 W2/W3 并行 | 七张事实卡字段统一；中国版边界明确；易变信息有复核日期 |
| W5 七款统一实测 | P1 | 逐款执行共同任务并保存操作、输出、异常、验证和恢复证据 | W1、W3 的任务脚本与验收冻结；产品可用性 | 每款都有完整记录；无法测试的原因明确标“待确认”，不补写结论 |
| W6 产品章节与截图 | P1 | 写第 5—8、12—13 章并制作正式截图说明 | W4；相应产品的 W5 记录 | 产品页先讲适用对象与问题，再讲功能；截图不作装饰 |
| W7 横向结论 | P1 | 写第 14 章和选择表 | 七款或可比子集的 W5 完成；比较维度已冻结 | 结论绑定场景和条件；事实与判断分开；无总排名 |
| W8 工作流进阶 | P2 | 写模板、Skill、Harness、多 Agent 与自动化 | W3；Harness 失败恢复案例 M-09 | 每个概念由实际任务引入；Harness 包含失败、调整和复测 |
| W9 代码专项 | P2 | 写第 19—23 章，覆盖改前基线、审查、测试与回退 | M-08；Codex/Qoder/ZCode 相应实测 | 不只展示生成代码；每个案例包含验证和恢复 |
| W10 新手试读 | P1 | 由真实零基础读者执行首发路径并记录阻塞点 | D-03、D-04；W2、W3 首稿 | 若实施，反馈取得适当同意并与模拟反馈分开；修订项可追踪 |
| W11 编辑与发布准备 | P1 | 一致性、事实、可访问性、风险和链接审校；决定网站与视觉方案 | W2—W7；D-05、D-06；W10（若实施） | 章节、图片、替代文字、日期和更新记录齐全；部署仍须单独人工授权 |

## 2. 推荐执行顺序

1. 先完成 W0，尤其是首发范围和第一篇案例；
2. W1 建立统一记录方式，防止后续七款产品留下不可比较的证据；
3. W2 与 W3 形成首发最小闭环；
4. W4 可在 W2/W3 期间并行整理，但涉及易变信息时必须保留复核标记；
5. 用 W3 已冻结的案例脚本执行 W5，再写 W6；
6. W7 必须等待可比实测，不能从界面印象直接推导；
7. W8、W9 在基础闭环稳定后推进；
8. 若作者选择真实读者测试，W10 应在发布前完成；
9. W11 完成内容发布准备，但网站部署、公开发布、购买服务仍需人工单独决定。

## 3. 各章节统一写作模板

每一产品页或案例建议按下列顺序写：

1. 适合谁、解决什么问题；
2. 测试条件：日期、地区、产品线、版本、账号和环境；
3. 任务输入、允许范围、禁止动作和验收条件；
4. 入口与关键界面；
5. 操作过程和 Agent 当前进度；
6. 权限、成本、发送或发布风险；
7. 输出结果及验证；
8. 失败、恢复和替代路径；
9. 事实、实测、作者经历与待验证判断；
10. 更新时间和后续复核项。

## 4. 质量门槛

### P0：事实与安全

- 未确认信息不写成事实；
- 模拟反馈不冒充真实研究；
- 作者账号个案不外推；
- 高风险动作明确要求人工决定；
- 中国版、国际版、旧产品和旧活动不混用；
- 版本、价格、Credits、活动、账号与地区信息均带日期。

### P1：新手可执行

- 不要求读者先掌握终端、Git 或模型供应商；
- 每个任务说明文件位置、Agent 进度和完成标准；
- 截图解释入口、操作、结果或风险；
- 每个案例包含检查结果与失败恢复；
- 工具选择建立在场景上，不堆砌功能。

### P2：可维护与可扩展

- 易变事实集中维护；
- 页面文件名、更新时间和图片替代文字统一；
- 模板、Skill、Harness 和多 Agent 的依赖关系清楚；
- 网站方案不反向绑架内容结构。

## 5. 阻塞关系摘要

- D-02 第一案例未定 → W3、W5 无法冻结；
- W5 统一实测未完成 → W7 横向结论不能正式写；
- M-09 失败恢复案例未补 → Harness 章节不能验收；
- M-08 代码验证样例未补 → 代码专项不能验收；
- D-03/D-04 未定 → 真实新手测试不可启动；
- D-05/D-06 未定 → 网站与视觉实现不可启动，但不阻塞 Markdown 内容写作。
