# 桌面 Agent 统一截图计划

> 目标：补齐最终交付体验证据，不重新运行任务，不额外消耗 Credits/API。  
> 操作人：由测试者自行截图；不远程接管电脑。

## 1. 截图原则

- 只截当前仍能打开的持久状态：历史任务、最终回复、文件、变更页、设置页和账单记录。
- 已经消失的权限弹窗、运行动画或报错不重新触发；在运行记录中保留文字事实即可。
- 截图应尽量同时包含产品名称或界面特征、当前任务以及被证明的内容。
- 不为追求统一构图而改变本轮文件、设置、模型或权限。
- 如果产品没有某项功能，记录“未发现/不提供”，不要用外部编辑器或 Git 客户端冒充产品能力。
- 截图只证明界面当时可见的事实；读取边界、自检遗漏等仍以产物和验收记录为证据。
- 个别产品的特殊细节（如变更统计、分段计费、自检恢复过程）不必专门补拍，以运行记录文字为准；通用 6 组截图已覆盖主要证据。

## 2. 截图精简呈现规范：只拍核心，一眼看懂

### 2.1 用途与目标受众先行

教程截图服务于两类读者：

- 零基础新手：需要「照着界面找得到」——截图必须突出产品身份、关键按钮、状态与数字，让他们在真实界面中能对上号；
- 横向比较者（包括作者自己）：需要「证据可核对」——用时、成本、产物数、变更统计等数字必须清晰可见。

因此每张截图只回答一个问题，与这个问题无关的元素一律不进入画面。

### 2.2 三层取舍标准

| 层级 | 判定 | 处理 |
|---|---|---|
| 必留 | 直接回答本图问题的核心元素：产品名/版本、模式/模型/权限值、用时/成本数字、产物与变更条目 | 放在画面主体（≥60% 区域），保证清晰可读 |
| 可留 | 帮助定位的少量上下文：当前任务名、模式标签、当前目录短路径 | 压缩到角落，不超过画面 1/4 |
| 必删 | 装饰与无关信息：推广横幅、推荐卡片、新手引导、通知角标、历史任务列表、无关侧栏面板、壁纸与渐变装饰 | 通过取景、滚动、调整窗口宽度排除，不用模糊 |

### 2.3 六组核心截图的呈现重点

| 编号 | 截图 | 用途（回答什么问题） | 画面必含 | 可省略/裁剪 |
|---|---|---|---|---|
| 01 | 入口与版本 | 这是哪款产品、哪个版本 | 产品名、版本号、标志性入口布局 | 欢迎页装饰、推广内容、账号菜单 |
| 02 | 任务配置 | 这轮任务怎么设置的 | 工作空间路径、模式、模型/Auto、推理强度、权限策略 | 输入框内完整提示词（正文以文字给出） |
| 03 | 最终回复与计费 | 结果如何、成本多少 | 完成摘要、用时、Credits/积分/人民币数字 | 长回复全文、表情与装饰元素 |
| 04 | 产物与预览 | 交付了什么、能否预览 | 产物文件名列表、`01-project-summary.md` 渲染效果 | 空目录、非本轮交付文件 |
| 05 | 变更与 diff | 改了什么、差异清楚吗 | 变更统计（如 +647/-0）、文件列表、行级 diff | 未改动文件、diff 中的空白行 |
| 06 | 自检与历史 | 自检说了什么、有无历史/恢复 | 自检结论、Git 状态/历史/恢复入口 | 自检全文、无关仓库信息 |

### 2.4 通用省略清单（所有截图一律不拍）

- 侧边栏历史任务、会话、项目列表；
- 推荐内容、热门话题、新手引导与提示卡片；
- 通知角标、系统托盘、浏览器书签等桌面私人信息；
- 账号头像、邮箱、用户 ID、API Key、Endpoint、支付信息与账户总余额；
- 工作空间之外的绝对路径（当前目录保留短路径即可）；
- 与任务无关的装饰性图标、横幅、渐变背景。

### 2.5 排版与取景要求

- 一图一焦点：主角区域占画面主体，辅助信息放角落；
- 先取景后裁剪：优先通过缩放与窗口调整排除无关区域，残留空白用裁剪去除，不用模糊遮挡；
- 数字优先：关键数字（用时、Credits、产物数、变更统计）不得因缩放而模糊；
- 不叠加弹窗、不拼接多窗口、不加装饰边框与阴影；
- 提示词全文、产物全文等长文本以正文/附件形式提供，不占用截图画面。

## 3. 每款可运行产品的最小必拍清单

在不重复执行任务的前提下，每款产品尽量保存以下 6 组证据。一张图能同时证明多项时不必拆图。

| 编号 | 必拍内容 | 需要证明什么 |
|---|---|---|
| 01 | 产品名称、版本与任务入口 | 使用的是哪一款桌面版、具体版本和工作/代码入口 |
| 02 | 本轮任务配置 | 工作空间、任务模式、模型/Auto、推理强度、权限策略；敏感字段必须遮挡 |
| 03 | 最终回复与计费 | 完成摘要、用时、Credits/积分/人民币费用；产品不显示的项目不强求 |
| 04 | 六份产物列表 + `01-project-summary.md` 预览 | 产物是否齐全、入口是否清楚、Markdown 实际渲染效果 |
| 05 | 文件变更列表 + `01-project-summary.md` 逐文件 diff | 新增/修改/删除是否完整、具体差异是否容易核对 |
| 06 | `06-self-check.md` 预览 + Git/历史/恢复入口 | 自检如何呈现，以及产品是否提供仓库状态、历史或恢复能力 |

如果 04、05、06 无法各自用一张图完整表现，可以拆成“列表”和“详情”两张；截图数量不是评分项，证据清楚即可。

## 4. 脱敏检查

每张图保存前检查：

- [ ] 账号名、邮箱、头像、用户 ID 已隐藏；
- [ ] API Key、Token、Endpoint 和连接器信息已隐藏；
- [ ] 无关历史任务、项目和聊天内容已隐藏；
- [ ] 本机用户名及工作空间之外的绝对路径已隐藏；
- [ ] 付款方式、订单号、余额和不需公开的额度已隐藏；
- [ ] 浏览器书签、通知、系统托盘等无关私人信息未入镜。

保留本轮实际 Credits/积分和人民币任务费用，因为它们是横评证据；只遮挡账户总余额、付款资料与身份信息。

## 5. 文件命名与提交方式

截图放入对应运行目录的 `evidence/screenshots/`，推荐使用：

```text
01-entry-and-version.png
02-run-settings.png
03-final-summary-and-cost.png
04-output-files.png
04-artifact-preview.png
05-change-list.png
05-file-diff.png
06-self-check.png
06-git-or-recovery.png
```

不存在的证据不要创建空白图片；在该产品的 `run-record.md` 中写明“产品不提供”“当前历史任务中未发现”或“瞬时界面未留存，不重新触发”。

截图完成后只需要告知：产品名、已保存的文件名，以及哪一项无法找到。届时再统一做脱敏复核、图注、产品内体验评分和教程选图。
