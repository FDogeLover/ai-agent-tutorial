# 读者学习路径

同一套教程需要允许不同读者从自己的问题出发，而不是强迫所有人走完全相同的路线。

## 路线 A：我从未使用过 Agent

建议顺序：第 1—10 章 → 选择一个案例 → 第 23 章。

阶段成果：

1. 能解释 Agent 的能力与风险；
2. 能选择一款工具完成低风险任务；
3. 能编写任务卡并验收结果；
4. 能形成基本的使用习惯。

## 路线 B：我主要处理办公与生活事务

建议顺序：第 2、4—12 章 → 工作与生活案例 → 第 14、23 章。

阶段成果：

1. 建立适合自己的任务模板；
2. 知道哪些操作必须人工确认；
3. 能跨文档、网页和表格组织任务；
4. 形成个人协作约定。

## 路线 C：我会使用 Agent，但不稳定

建议顺序：第 7—18 章 → 对照自己的失败案例完成复盘。

阶段成果：

1. 找到上下文、权限、执行或验证环节的问题；
2. 把重复需求沉淀为模板或 Skill；
3. 建立最小 Harness；
4. 用反馈回路持续改进。

## 路线 D：我想用于软件项目

建议顺序：第 7—10、13—18、22 章。

阶段成果：

1. 能让 Agent 在现有项目中安全工作；
2. 能设计项目规则、专用 Skills 和验证流程；
3. 能判断是否需要多 Agent；
4. 能把项目经验固化为工程资产。

## 路线 E：我想设计自己的 Agent 工作系统

建议顺序：快速浏览第 1—14 章 → 深入第 15—18 章 → 完成第 23 章。

阶段成果：

1. 画出系统各组成部分及信息流；
2. 明确权限边界和人工检查点；
3. 为高频任务提供专用能力；
4. 建立可观察、可验证、可恢复的工作方式。
