# 七款 Agent 的分类方法

## 结论

对零基础读者，先用四组介绍产品最容易理解；进行实际选型时，再用多维标签交叉判断。这样既保留直观性，也避免把地区、任务方向和开源程度误认为同一种分类标准。

## 面向读者的四组结构

### 1. 海外闭源托管型综合 Agent

代表产品：Claude、Codex。

叙事重点：它们在工作事务、代码和设计等多个方向具有较强的综合能力，产品成熟度和工具生态值得重点体验。教程不直接使用“统治力”作为结论，而是通过统一测试说明它们在哪些任务上处于第一梯队，以及在哪些条件下仍有局限。

需要说明：这里评测的是具体桌面 Agent 产品和图形化使用入口，不只是底层闭源模型。

### 2. 国内综合型 Agent

代表产品：TraeWork 中国版、Work Buddy。

叙事重点：综合任务覆盖、中文交互、本地化场景、使用便利度、免费额度和新手上手体验。

国内与海外可以帮助读者理解服务环境和本地化差异，但不能代替能力测试。

### 3. 代码优先型 Agent

代表产品：Qoder 中国版、ZCode 中国版。

叙事重点：它们更围绕软件开发过程展开，应重点测试图形化项目导入、项目理解、代码定位与修改、差异查看、测试验证和长任务处理。

这类产品的评价不应只看“代码能不能生成”，还要看是否理解现有项目、是否控制修改范围、能否验证结果以及出现错误后是否容易恢复。

### 4. 开源自主型 Agent

代表产品：Hermes。

叙事重点：桌面图形版所提供的自主性、可定制性和运行自由，同时说明安装配置、工具接入、权限管理和故障排查所需要的计算机基础。

“极客风”可以作为通俗描述，但要进一步解释它意味着什么：用户通常拥有更多控制权，也需要承担更多配置、资源、安全和维护责任。

正式写作前，应核对 Hermes 桌面图形版的完整项目名称、版本、官方项目地址、支持系统和实际运行方式，避免与同名模型、命令行版本或其他项目混淆。

## 用于选型的五个辅助维度

| 维度 | 需要回答的问题 |
|---|---|
| 任务方向 | 更偏综合工作、代码、设计、研究，还是自主执行？ |
| 开放程度 | 产品代码、扩展接口和底层模型分别开放到什么程度？ |
| 运行方式 | 在统一的桌面 GUI 前提下，能力主要由云端、本地还是自托管环境提供？ |
| 自主程度 | 每一步都需要确认，还是可以连续规划并调用工具？ |
| 使用门槛 | 零基础能否仅通过图形界面完成，是否仍要求编程或系统配置经验？ |

地区作为补充信息单独记录，用于解释语言、本地化、付款、网络、数据位置和支持渠道，不直接推导产品能力。所有产品均只比较桌面图形界面版本，CLI/TUI 不进入主表。

## 工作分类矩阵

| 入门分组 | 产品 | 核心观察方向 | 预计主要读者 |
|---|---|---|---|
| 海外闭源托管型综合 Agent | Claude、Codex | 工作、代码、设计的综合能力与服务边界 | 希望使用成熟综合工具的读者 |
| 国内综合型 Agent | TraeWork 中国版、Work Buddy | 中文、本地化、综合任务与上手便利度 | 国内零基础或日常办公用户 |
| 代码优先型 Agent | Qoder 中国版、ZCode 中国版 | 项目理解、代码修改、验证与开发环境融合 | 软件开发或准备学习编程的用户 |
| 开源自主型 Agent | Hermes | 自主性、可定制性、部署、权限与维护 | 有计算机基础、重视控制权的用户 |

这张表是写作假设，不是最终结论。产品体验完成后，应根据实际证据调整描述。

## 推荐的章节呈现顺序

每组先写一页“这类 Agent 适合解决什么问题”，再写具体产品体验，最后增加组内小结。七款全部介绍完后，再用统一矩阵做跨组选择，而不是边介绍边宣布总排名。
