# 网站设计调研：同类教程/文档站参考分析

> 页面标识：doc-13-site-design-research
>
> 调研日期：2026-08-13｜调研方式：抓取 6 个代表性站点页面并分析结构
>
> 用途：为「AI Agent 零基础教程」网站部署提供布局、排版与美学设计参考，产出可直接执行的视觉规范与选型建议。

## 1. 调研目的与结论速览

### 为什么先调研

教程内容（23 章 + 序章 + 附录）已全部成稿。网站部署前先看同类站，避免「内容很好、界面劝退」。参考对象分三类：**书式教程站**（本书最接近的形态）、**长文/文章站**（单篇精读体验）、**现代文档站**（组件与交互范式）。

### 结论速览（给决策者）

1. **形态**：本书应采用「现代文档站三栏布局 + 书式章节组织」——左侧章节树（全书 6 篇 23 章）、右侧页内大纲、正文窄栏（约 720px）；
2. **美学**：推荐「清爽学术风」——白/暖白背景、深灰文字、单一强调色（蓝或紫），浅/深双模式；避免花哨渐变与营销页风格；
3. **组件**：至少实现 6 类——提示框（Note/Warning/Danger）、卡片组、步骤条、代码块、表格、截图组件（带图注）；
4. **技术选型**：开源自托管优先（VitePress / Astro Starlight / Docusaurus），Mintlify 托管作对比项；
5. **易变信息处理**：价格/版本集中展示区 + 核验日期角标（延续 `docs/07` 机制）。

## 3. 布局与信息架构：三种模式

### 模式 A：书式教程站（推荐主形态）

代表：hello-algo、d2l。结构：`顶栏(书名/搜索/主题切换) + 左侧章节树(可折叠) + 正文窄栏 + 上一篇/下一篇`。

- **优点**：章节树与本书「六篇 23 章」天然匹配；阅读路径线性可控；支持深链到小节；
- **代价**：右侧无大纲时长文定位略弱 → 建议补一个右侧大纲（见模式 C）；
- **对本书**：首页 + 阅读页 = 本模式；章节树直接映射 `chapters/README.md` 索引。

### 模式 B：长文窄栏（用于首页叙事与精选文章）

代表：Anthropic。结构：`窄栏居中(680–720px) + 无侧栏 + 顶部导航`。

- **优点**：专注、杂志感、适合「序章」「30 天计划」这类线性阅读；
- **对本书**：首页的「为什么读这套教程」导读、每章正文可保持窄栏排版。

### 模式 C：现代文档站三栏（用于产品页与选型页）

代表：Mintlify、Tailwind、LangChain。结构：`左侧目录 + 正文 + 右侧页内大纲 + 顶部搜索`。

- **优点**：信息密度高、跳转快；产品页（第 5 章七款）、选择表（第 6 章）需要这种「可扫读」布局；
- **对本书**：产品页与对比表页采用三栏，概念章采用模式 A。

**结论：全站统一导航壳（顶栏 + 左侧章节树 + 搜索），正文页按内容类型在「单栏窄排（概念章）」「两栏（带右侧大纲）」间切换。**

## 4. 排版与美学规范（可直接落地的规格）

### 4.1 字体与正文

| 项 | 建议值 | 参考来源 |
|---|---|---|
| 正文宽度 | 680–720px（单栏）；三栏时正文区同宽 | Anthropic、Mintlify |
| 正文字号 | 16–17px（中文建议 16px 起） | Tailwind |
| 行高 | 1.7–1.8（中文长文舒适区间） | d2l |
| 中文正文 | 思源黑体/系统无衬线栈（`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei"`） | hello-algo |
| 标题字体 | 与正文同族加粗；章节标题带编号（「第 1 章」「7.1」） | d2l、hello-algo |
| 代码/等宽 | JetBrains Mono / 系统等宽栈 | Tailwind |

### 4.2 配色（两套建议方向，任选其一）

**方案 A：清爽学术蓝（推荐，稳妥）**
- 背景：`#FFFFFF`（亮）/ `#0F1115`（暗）；文字：`#1A1A1A` / `#E5E7EB`
- 主色：蓝 `#2563EB` 系；链接与强调用它
- 副色：绿（成功/通过）、琥珀（警告）、红（危险）用于提示框

**方案 B：暖纸橙（有辨识度，接近 Anthropic 气质）**
- 背景：`#FAF9F5`（暖米色）/ 暗色 `#1C1917`
- 主色：赭橙 `#C15F3C`；正文深灰褐 `#333`

### 4.3 组件清单（MVP 必须）

| 组件 | 用途 | 参考实现 |
|---|---|---|
| Callout 提示框 | Note / Tip / Warning / Danger 四色 | Mintlify、VitePress |
| 章节卡片（首页） | 六篇入口 + 七款产品入口 | Mintlify Card |
| 步骤条（Steps） | 「跟着做」章节（01–06 编号） | Tailwind、Mintlify |
| 代码块 | 含语言标签、复制按钮、深色底 | Tailwind |
| 表格 | 评分表、对比表、检查清单（响应式横向滚动） | 各站 |
| 截图组件 | 图注 + 版本/日期角标 + 替代文字（呼应 `docs/03` 规范） | Mintlify Frame |
| 面包屑 + 上一篇/下一篇 | 章节导航 | hello-algo、d2l |
| 主题切换（浅/深） | 跟随系统 + 手动 | 各现代站 |

### 4.4 首页设计（信息架构建议）

```
首页
├─ Hero：一句话定位 + 「开始阅读」主按钮（→ 序章/第一篇）
├─ 六篇入口卡片（认识 → 选型 → 任务 → 工作流 → Harness → 案例）
├─ 七款产品卡片（对应第 5 章，各带「一句话结论」）
├─ 三条学习路径（路线 A–E 简化为 3 条：零基础 / 办公 / 进阶）
├─ 易变信息提示（价格核验日期条）
└─ 页脚（GitHub 仓库、反馈入口）
```

## 5. 技术选型建议

| 方案 | 成本 | 中文/MD 支持 | 三栏/组件 | 适合度 | 说明 |
|---|---|---|---|---|---|
| **VitePress**（推荐） | 免费开源 | 优秀 | 默认两栏+大纲，可扩展 | ★★★★★ | MD 直接渲染、零配置、浅深模式、搜索插件、可部署 GitHub Pages/Cloudflare |
| **Astro Starlight** | 免费开源 | 优秀 | 内置三栏+目录组件 | ★★★★★ | 内容岛架构、性能好、扩展性强 |
| **Docusaurus** | 免费开源 | 良好 | 三栏+丰富插件 | ★★★★ | React 生态、文档站最成熟，稍重 |
| **Material for MkDocs** | 免费开源 | 优秀 | 两栏+插件丰富 | ★★★★ | hello-algo 同款，但左侧树在移动端一般 |
| **Mintlify Hobby** | 免费（带品牌）/ Pro $250/月 | 良好 | 三栏+组件最全 | ★★★ | 托管省事、AI 搜索/MCP；对个人教程 Hobby 有平台标识，Pro 偏贵 |

**建议**：VitePress 或 Astro Starlight 起步（内容已是结构化 Markdown + 元数据头，迁移成本最低）；后续要 AI 检索（llms.txt / MCP）可在任选方案上加插件；托管用 GitHub Pages / Cloudflare Pages 零成本。

## 6. 「借鉴 / 避免」清单

### 借鉴

- ✅ 左侧章节树 + 正文窄栏 + 右侧大纲（三栏文档站范式）；
- ✅ 章节统一结构带来可预期性（d2l：每章固定节奏；本书：模板结构已在正文实现）；
- ✅ 加粗引导语 + 列表打散长文（Anthropic 可扫描性）；
- ✅ 「概念→图示→适用→实例」图文节奏（Anthropic）；
- ✅ 步骤编号化（Tailwind 01–06）；
- ✅ 易变信息集中 + 核验日期角标（延续 `docs/07`）；
- ✅ 截图组件带图注/版本/替代文字（呼应 `docs/03` 与截图精简规范）。

### 避免

- ❌ 营销页式大 Hero 渐变与动效堆叠（本书是教程不是 SaaS 落地页）；
- ❌ 纯白高对比刺眼排版（正文用深灰而非纯黑）；
- ❌ 把所有章都做成三栏高密度页（概念章需要单栏专注，产品页才需要高密度）；
- ❌ 无移动端适配的固定侧栏（移动端应折叠为抽屉）；
- ❌ 把价格/福利写死在正文（必须走易变信息区，避免 `docs/07` 记录的过期问题重演）；
- ❌ 忽略替代文字与可访问性（`docs/03` 已要求页面不依赖图片）。

## 7. 下一步建议

1. 确认配色方案（A 清爽蓝 / B 暖纸橙）与选型（VitePress / Starlight）；
2. 用 1 个代表页（如第 7 章任务卡 + 第 6 章选择表）做 1 页模板试渲染，验证三栏与组件效果；
3. 确认后批量生成全部页面、配置导航/搜索/主题，部署到 GitHub Pages / Cloudflare Pages。
