# 内容开发清单

## 第一阶段：完成最小可读版本

- [ ] 写序章：作者经历与教程承诺；
- [ ] 写第 1 章：Agent 是什么；
- [ ] 写第 2 章：能力、边界与风险；
- [ ] 写第 4 章：选择维度；
- [ ] 写第 7 章：任务卡；
- [ ] 写第 10 章：验收与复盘；
- [ ] 完成一个工作或生活案例；
- [ ] 完成术语表和任务卡模板。

目标：让零基础读者无需等待全书完成，也能走通一次完整任务。

## 第二阶段：补齐选型与工具体验

- [ ] 为七款 Agent 建立统一体验记录；
- [ ] 选择一个所有产品都能尝试的基准任务；
- [ ] 记录桌面客户端版本、操作系统、硬件环境、日期、权限方式和结果；
- [ ] 记录下载安装、登录、首次授权和第一个任务的完整新手路径；
- [ ] 总结适用人群与限制；
- [ ] 编写个人选型练习。

目标：帮助读者形成自己的选择，而不是复制作者的选择。

## 第三阶段：加入作者的实践资产

- [ ] 盘点已经创建的 Skills；
- [ ] 选择一个简单 Skill 做完整拆解；
- [ ] 选择一个复杂 Skill 展示迭代过程；
- [ ] 整理现有 Harness 架构；
- [ ] 找出一次失败或返工经历；
- [ ] 把架构整理成最小版、进阶版和完整版本。

目标：形成教程最具辨识度的核心内容。

## 第四阶段：案例与发布

- [ ] 至少完成一个工作案例；
- [ ] 至少完成一个生活案例；
- [ ] 至少完成一个内容或研究案例；
- [ ] 至少完成一个项目搭建案例；
- [ ] 招募 2—3 位零基础读者试读；
- [ ] 根据卡点修改术语、步骤和练习；
- [ ] 确定最终发布载体。

目标：用真实读者验证教程是否真的通俗、可执行。

## 素材采集建议

后续每次使用 Agent 时，可以保存：

- 任务为什么出现；
- 最初怎样描述；
- Agent 第一次做错了什么；
- 哪条补充信息改变了结果；
- 怎样验收；
- 哪些步骤值得模板化或做成 Skill；
- 如果重新做一次，会怎样设计 Harness。
