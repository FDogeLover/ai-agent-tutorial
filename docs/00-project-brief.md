# 教程定位与边界

## 一句话定位

这不是一份 Agent 产品说明书，而是一套帮助普通人学会选择、使用、管理并逐步定制 AI Agent 的实践教程。

## 核心主张

### 以任务为中心，而不是以产品为中心

读者真正关心的是“我能否完成这件事”。产品只在选型和实操中出现，主体知识应尽量跨产品复用。

### 先建立正确预期，再教授具体技巧

Agent 能执行任务，但不等于可以放弃监督。教程需要同时讲清能力、边界、失败方式和人的责任。

### 先完成一个小闭环，再逐步工程化

新手的第一个目标不是搭建复杂系统，而是完成一次范围明确、风险可控、能够验收的任务。模板、Skills 与 Harness 都应从真实的重复需求中生长出来。

### 每一章都要产生可带走的成果

成果可以是一份任务卡、选择矩阵、检查清单、Skill、项目规则或 Harness 草图。读者不只“看懂”，还要逐步拥有自己的 Agent 工具箱。

## 内容边界

### 版本与交互范围

主教程只介绍具有图形化界面的桌面版 Agent。读者应能通过窗口、菜单、按钮、表单、文件选择器和可视化任务面板完成主要操作，不要求使用 CLI 或 TUI。

软件可以在后台调用命令、连接云端服务或使用本地运行环境；判断标准是普通读者是否需要亲自进入命令行界面。确实无法避免的高级命令行内容，只能作为明确标记的选读附录出现。

产品地区范围固定如下：Qoder、TraeWork、ZCode 均以中国版桌面客户端和中国站官方资料为准。不得用国际站的价格、套餐、模型入口或活动福利替代中国版信息；同一品牌下的 IDE、Work、CLI 等产品线也必须分别核对。

教程会覆盖：

- Agent 的基本概念、工作方式和常见误区；
- 产品选择方法，以及多款 Agent 的实际体验；
- 任务描述、上下文、权限、执行、验证和复盘；
- 工作、生活、研究、内容创作和软件项目案例；
- Skills、规则、记忆、工具连接与多 Agent 协作；
- Harness 的组成、设计原则和演进方式。

教程不会：

- 把任何产品描述为适合所有人的“唯一最佳选择”；
- 把可能变化的价格、功能和模型信息写成长期不变的结论；
- 鼓励读者在不了解后果时开放高风险权限；
- 用复杂术语代替可执行的方法；
- 假设读者已经会编程、命令行或版本控制。
- 在主线教程中使用 CLI/TUI 版本替代桌面图形界面版本；

## 差异化价值

教程的独特性来自两类内容：

1. 作者对 Codex、Claude、ZCode 中国版、TraeWork 中国版、WorkBuddy、Qoder 中国版、Hermes Desktop 的真实使用观察；
2. 作者从项目搭建中沉淀出的 Skills、Harness 架构、失败案例和改进过程。

“真实经验”不只展示成功结果，还应包含最初做法、遇到的问题、判断过程、修改方案和最终可复用原则。

## 建议的内容载体

- 主教程：结构稳定的长文或电子书；
- 快速上手卡：适合第一次使用时照着操作；
- 案例库：按工作、生活、创作和开发场景持续扩展；
- Agent 档案：记录具体产品体验并标注测试日期与版本；
- 模板库：任务卡、验收清单、Skill 模板和 Harness 模板。
