# 完整目录与章节目标

## 序章：为什么现在需要 Agent 素养

### 0. 我为什么写这套教程

- 作者使用不同 Agent 的经历；
- 从“问 AI”到“与 Agent 一起完成任务”的转变；
- 本教程适合谁，以及如何阅读。

本章产出：读者写下一个希望由 Agent 协助完成的真实任务。

## 第一篇：先认识你的新搭档

### 1. AI Agent 到底是什么

- 普通聊天、Copilot 与 Agent 的区别；
- Agent 如何理解目标、使用工具、执行步骤和反馈结果；
- 用生活化比喻解释模型、上下文、工具、记忆与权限。

本章产出：一张 Agent 工作流程图。

### 2. Agent 能做什么，不能做什么

- 适合委派的任务特征；
- 不适合完全自动执行的任务；
- 幻觉、遗漏、误操作、权限和隐私风险；
- “能生成结果”不等于“结果可信”。

本章产出：任务适配性检查表。

### 3. 人与 Agent 怎样分工

- 人负责目标、取舍、授权和最终责任；
- Agent 负责检索、整理、生成、执行和重复劳动；
- 监督强度如何随风险变化；
- 从一次性问答到持续协作。

本章产出：个人的人机分工表。

## 第二篇：选择适合自己的 Agent

### 4. 不背产品参数，先看选择维度

- 四组入门认识：海外综合型、国内综合型、代码优先型、开源自主型；
- 再用任务方向、开放程度、后台运行方式、自主程度和使用门槛进行交叉判断；
- 主要任务：办公、生活、研究、内容或开发；
- 工作对象：网页、文档、代码、软件界面或外部服务；
- 桌面环境：支持的操作系统、安装方式、硬件要求和更新方式；
- 图形界面：安装登录、导航、文件导入、任务观察和权限确认是否直观；
- 自主程度、可控程度、生态、成本和学习门槛；
- 隐私、权限和组织合规要求。

本章产出：个人 Agent 需求卡。

### 5. 七款 Agent 的实际体验

第 5 章采用“一个总览页 + 七个独立产品页”的结构。四类分组用于帮助新手建立第一印象，不作为能力高低排名。

#### 5.0 四类 Agent 总览

1. **海外闭源托管型综合 Agent**：Claude、Codex。重点观察工作事务、代码与设计任务的综合能力，以及官方托管服务带来的便利和边界；
2. **国内综合型 Agent**：TraeWork 中国版、WorkBuddy。重点观察中文环境、本地化场景、桌面上手体验与综合任务覆盖；
3. **代码优先型 Agent**：Qoder 中国版、ZCode 中国版。重点观察项目导入、代码库理解、修改、差异查看、测试验证和对编程基础的要求；
4. **开源自主型 Agent**：Hermes Desktop。重点观察安装配置、自定义模型与工具、自主执行、权限控制和更高使用门槛。

总览页同时说明：产品分类只是入口；最终还要按任务、地区、价格、开放程度、自主程度、隐私要求和学习成本交叉判断。

#### 5.1 Claude 桌面版

- 体验海外闭源托管型综合 Agent 的工作、代码和设计能力；
- 核对官方订阅、免费使用限制、地区可用性和桌面端工作方式；
- 记录它对零基础用户的便利之处，以及闭源服务的边界。

#### 5.2 Codex 桌面版

- 体验其处理工作、代码、设计和完整项目交付的能力；
- 以官方订阅和官方模型为主要测试条件，不把第三方模型切换工具作为推荐入口；
- 观察项目理解、文件修改、工具调用、验证与恢复过程是否直观。

#### 5.3 TraeWork 中国版

- 只核对中国版账号、价格、额度与桌面功能，不混用国际站资料；
- 体验中文办公、文件整理、报告、表格和演示文稿等综合任务；
- 观察订阅档位、任务过程反馈和本地化上手体验。

#### 5.4 WorkBuddy 桌面版

- 体验中文办公、文件处理和跨应用工作流；
- 核对订阅、Credits、新用户福利及其有效期限；
- 观察任务执行的透明度、人工接管方式和失败恢复路径。

#### 5.5 Qoder 中国版

- 只核对中国版 IDE、账号、人民币价格和中国版活动；
- 区分 Qoder 与其他同品牌产品线，避免混用福利信息；
- 体验现有代码项目的阅读、修改、测试和变更说明能力。

#### 5.6 ZCode 中国版

- 只核对中国版账号、额度、模型和活动规则；
- 体验代码项目理解、修改、验证，以及 API Key 与自定义供应商能力；
- 观察它对编程新手是否提供足够清晰的界面引导与错误解释。

#### 5.7 Hermes Desktop

- 体验开源、自托管与高自主化带来的自由度；
- 观察自定义模型、Skills、自动化或持续任务的配置过程；
- 如实说明安装、依赖、权限和故障排查为何更适合有一定计算机基础的用户。

七个产品页统一采用十段式结构：一句话结论；测试版本和地区；下载、安装与首次启动；免费额度、订阅与计费；核心能力；界面与工作方式；共同基准任务、优势任务与边界任务；遇到的问题与恢复；适合与不适合；最终结论。所有易变信息标注最后核验日期，所有体验标注操作系统、桌面客户端版本和运行方式。

本章产出：七份可独立阅读、又能相互比较的体验报告。

### 6. 横向比较与个人选型

- 汇总七款产品在同一基准任务中的实际表现，不做脱离场景的总分排名；
- 按人群、任务、地区、预算、开放程度、隐私和学习成本建立选择矩阵；
- 先选场景，再选产品，并区分主 Agent、辅助 Agent 与专用工具；
- 说明什么时候适合继续免费试用、购买官方订阅、组合使用或切换产品；
- 提供可复用的个人试用流程，让读者用自己的真实任务再次验证选择。

本章产出：一张横向选择表、一条新手决策路径，以及一份有理由的个人选型结论。

## 第三篇：完成你的第一个 Agent 任务

### 7. 从“帮我做一下”到清晰任务卡

- 目标；
- 上下文；
- 输入材料；
- 范围与约束；
- 交付物；
- 验收标准。

本章产出：第一张可执行任务卡。

### 8. 在安全边界内让 Agent 行动

- 只读、写入、执行与外部操作的区别；
- 如何逐步开放权限；
- 敏感信息、支付、删除、发送和发布操作；
- 备份、版本记录与可撤销性。

本章产出：个人权限分级表。

### 9. 跟进过程，而不是只等最终答案

- 什么时候应让 Agent 自主推进；
- 什么时候应分阶段确认；
- 如何处理中断、追问、偏航和失败；
- 进度更新中真正值得关注的信息。

本章产出：任务过程检查清单。

### 10. 验收、纠错与复盘

- 事实核查、计算复核、文件检查和实际测试；
- 区分“表达不好”和“任务失败”；
- 用验收反馈推动修正；
- 从一次任务中沉淀下一次可复用的经验。

本章产出：任务验收与复盘记录。

## 第四篇：把零散使用变成稳定工作流

### 11. 管理上下文

- Agent 需要知道什么；
- 文件、链接、截图、规则和历史记录的作用；
- 上下文不足、过载和污染；
- 长任务如何分阶段保存状态。

本章产出：项目上下文清单。

### 12. 建立自己的模板库

- 哪些内容适合模板化；
- 任务模板、检查清单、输出格式和案例模板；
- 避免把模板写成僵硬的“万能提示词”；
- 版本迭代与适用范围。

本章产出：三个个人常用任务模板。

### 13. 从模板进阶到 Skill

- Skill 解决什么问题；
- Skill 与普通提示词、项目规则、脚本的区别；
- 指令、参考资料、脚本和资源如何组合；
- 什么时候该创建 Skill，什么时候不该；
- 用作者的 Skill 做完整拆解。

本章产出：第一个最小可用 Skill。

### 14. 规则、记忆与个人偏好

- 全局规则与项目规则；
- 长期偏好与临时上下文；
- 记忆的写入、更新和淘汰；
- 错误规则如何持续放大问题。

本章产出：个人 Agent 协作约定。

## 第五篇：理解并搭建 Harness

### 15. Harness 是什么

- 从“一个模型”转向“一个工作系统”；
- Agent、上下文、工具、权限、状态、验证和反馈回路；
- Harness 如何影响可靠性、成本和体验；
- 用一个完整任务观察 Harness 的运行。

本章产出：个人 Harness 草图。

### 16. 一个可演进的 Harness 架构

- 入口层：任务与意图；
- 上下文层：材料、规则、记忆与检索；
- 执行层：Agent、工具与子任务；
- 安全层：权限、隔离、审批与撤销；
- 验证层：测试、审查和验收；
- 反馈层：日志、复盘与知识沉淀。

本章产出：最小 Harness 设计表。

### 17. 多 Agent 协作不是越多越好

- 适合拆分的任务；
- 角色、边界、共享上下文和交付协议；
- 并行、串行、评审与仲裁模式；
- 重复劳动、冲突、上下文丢失和成本膨胀；
- 何时回到单 Agent。

本章产出：一个双 Agent 协作实验。

### 18. 让系统逐步变得可靠

- 失败分类与观察指标；
- 自动检查与人工检查；
- 小步修改、回归验证和可恢复设计；
- 把个人经验变为 Harness 资产。

本章产出：Harness 改进清单。

## 第六篇：真实案例

### 19. 工作事务案例
