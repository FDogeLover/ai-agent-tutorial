# 七款桌面 Agent 横向选择矩阵

> 状态：正式版（基于 2026-08-12 统一基准实测与 2026-08-13 截图核验）
>
> 数据底稿：`docs/12-benchmark-scoring.md`（六维评分与逐条证据卡）；运行记录见 `research/runs/*/run-record.md`；界面证据见 `docs/11-interface-guides/`
>
> 用途：帮助读者缩小试用范围；分维度比较，不做脱离场景的总分排名。

这里比较的是默认配置下的桌面 Agent 产品体验，而不是底层模型榜单。内容质量注明当次模式和模型条件；`Auto`、手动模型与 BYOK 结果分开呈现。不同产品的 Credits、积分、人民币与 API 账单不是同一单位，不按数值横比。

## 1. 先看能不能稳定使用

选型的第一步不是比较模型参数，而是确认：

1. 官方服务是否覆盖自己所在地区；
2. 是否能正常注册、登录、付费和续费；
3. 账号或服务中断时是否有申诉、导出和恢复路径；
4. 工作资料是否允许交给该服务处理；
5. 自己能否承担配置、维护和排错成本。

能力再强，如果账号无法稳定使用、费用无法支付或资料不允许上传，都不适合作为唯一主 Agent。本轮实测中 Claude 账号受限即为此类前置阻断案例。

## 3. 按读者情况缩小范围（含实测依据）

### 零基础、主要处理中文办公

先试 TraeWork 中国版和 WorkBuddy。实测两者均为 0 人工介入、无需配置模型；WorkBuddy 的预览与变更可见性更好（Markdown 渲染 + `+647/-0` 行级 diff），TraeWork 的 Work/Code/Design 三模式更直观。重点比较首次登录、文档导入、产物定位和 Credits 消耗。

### 主要处理代码项目

先试 Qoder 中国版和 ZCode 中国版，再用 Codex 做综合对照。Qoder 最快最省（2:00 / ¥0.25）且有审查提交能力；ZCode 的审查视图提供逐文件增删统计（+46、+37、+84 等），变更透明性最强；Codex 综合交付与审阅一致性最佳（全维度满分，支持审阅后直接提交推送）。测试必须使用同一个现有项目，并检查修改范围、差异、测试和变更说明。

### 希望工作、代码和设计由一个主 Agent 处理

在官方服务和账号条件满足时测试 Codex；同时用 TraeWork 中国版或 WorkBuddy 做本地化对照。Claude 的能力判断和账号稳定性判断必须分开——本轮实测中作者账号受限，能力无法进入统一任务验证。

### 重视模型自由、自托管和长期自动化

有系统配置经验时再测试 Hermes Desktop。实测中它提供了最灵活的预览/源码/差异/编辑四视图，也是唯一触发并自动恢复真实路径错误的样本；但模型账单、权限、运行环境和维护责任都由用户承担，首次配置门槛不能被已配置好的测试状态代表。

## 5. 证据边界与后续复核

本矩阵已基于七款产品的同一共同基准任务形成正式结论（2026-08-12），并满足：记录版本、地区、账号状态、订阅方案、用时、人工介入；结论回指运行记录、截图与官方来源；作者个案、实际测试、官方事实和推测被清楚区分。

仍需注意的边界（对应 benchmark v2 与后续维护）：

- 本轮仅覆盖「材料整理」单一任务，代码优先型产品的优势任务（代码理解、diff、验证、Git）尚未统一测试；
- TraeWork 与 QoderWork 的审阅/差异环节未留存截图，能力范围保持「未验证」；
- ZCode、Hermes 本轮 API 成本未记录，成本维度为「未知」；
- Claude 需在账号可用后补测；产品截图与价格随版本更新，正式发布前按 `docs/07` 复核清单逐项复核。
