# 七款桌面 Agent 横向选择矩阵

> 状态：框架版，尚未完成统一基准测试。
>
> 用途：帮助读者缩小试用范围，不作为总分排名。

这里比较的是默认配置下的桌面 Agent 产品体验，而不是底层模型榜单。正式矩阵将优先展示成品预览、产物导航、文件或 Git 变更、过程可控性、完成效率与实际成本。内容质量注明当次模式和模型条件；`Auto`、手动模型与 BYOK 结果分开呈现。

## 1. 先看能不能稳定使用

选型的第一步不是比较模型参数，而是确认：

1. 官方服务是否覆盖自己所在地区；
2. 是否能正常注册、登录、付费和续费；
3. 账号或服务中断时是否有申诉、导出和恢复路径；
4. 工作资料是否允许交给该服务处理；
5. 自己能否承担配置、维护和排错成本。

能力再强，如果账号无法稳定使用、费用无法支付或资料不允许上传，都不适合作为唯一主 Agent。

## 3. 按读者情况缩小范围

### 零基础、主要处理中文办公

先试 TraeWork 中国版和 WorkBuddy。重点比较首次登录、文档导入、任务反馈、产物定位、Credits 消耗和失败恢复，不必一开始学习自定义模型。

### 主要处理代码项目

先试 Qoder 中国版和 ZCode 中国版，再用 Codex 做综合对照。测试必须使用同一个现有项目，并检查修改范围、差异、测试和变更说明。

### 希望工作、代码和设计由一个主 Agent 处理

在官方服务和账号条件满足时测试 Codex、Claude；同时用 TraeWork 中国版或 WorkBuddy 做本地化对照。Claude 的能力判断和账号稳定性判断必须分开。

### 重视模型自由、自托管和长期自动化

有系统配置经验时再测试 Hermes Desktop。图形界面降低了操作难度，但不会替用户承担模型账单、权限、运行环境和维护责任。

- 所在地区和可用支付方式：
- 能接受的月度预算：
- 能否接受云端处理资料：
- 能否处理 API Key、模型供应商和环境配置：
- 账号中断时允许损失多少历史记录和时间：
- 我准备先试的两款产品及理由：

## 5. 何时形成正式结论

只有完成以下工作后，矩阵才从框架判断升级为正式选型结论：

- 七款产品完成同一共同基准任务；
- 每款完成一个优势任务和一个边界任务；
- 记录版本、地区、账号状态、订阅方案、用时、人工介入和恢复路径；
- 所有结论能够回指任务记录或官方来源；
- 作者个案、实际测试、官方事实和推测被清楚区分。
