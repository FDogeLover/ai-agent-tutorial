# 七款桌面 Agent 共同基准评分

> 数据日期：2026-08-12（运行记录）与 2026-08-13（截图核验）
>
> 评分对象：六款完成统一任务的正式产品 + QoderWork 扩展样本 + Claude 阻断案例
>
> 评分原则：分维度评分、证据卡呈现，不合成单一总分；结论使用「在什么条件下更适合谁」，不做绝对排名。

## 1. 评分方法与边界

### 1.1 比较对象

比较的是桌面 Agent 产品的**端到端交付体验**：用户把同一份材料与同一项任务交给产品后，能否在尽量少的人工介入下获得完整成品，并方便地预览、核对、修改与恢复。内容质量与成本、模型、Provider 一起记录，不单独归因于底层模型。

### 1.2 测试条件（全部记录，互不相同）

| 产品 | 模式与模型 | 权限设置 |
|---|---|---|
| WorkBuddy 5.3.11 | Auto；界面显示 GLM-5.2 | 默认 |
| TraeWork CN 0.1.47 | Work；默认/Auto；模型未记录 | 默认 |
| Qoder CN 1.23.0 | IDE / Quest Mode / Auto | 默认 |
| QoderWork CN 0.9.12 | 智能体 / Auto | 默认 |
| ZCode CN 3.7.6 | OpenCode Go / DeepSeek V4 Flash / 最高推理 | 变更前确认（BYOK） |
| Codex 26.803.10989.0 | gpt-5.6-sol / 高推理 | 请求批准 |
| Hermes 0.17.0 | OpenCode Go / DeepSeek V4 Flash / 最高推理 | 智能审批（BYOK） |
| Claude | 未进入统一任务 | 账号受限 |

分层：WorkBuddy / TraeWork / Qoder / QoderWork / Codex 属**产品托管路径**；ZCode / Hermes 属 **BYOK / 外部 Provider 路径**，其速度、质量与成本归因于「产品 + Provider + 模型 + 推理设置」组合，不与托管路径直接合并排名。

### 1.3 维度与记分

每个维度 1–5 分，附客观证据或作者观察；证据不足的维度记「—（无证据）」不评分。原始产物未修改，全部结论可回指 `research/runs/*/run-record.md` 与截图。

| 维度 | 考察内容 |
|---|---|
| 交付成果 | 6 份文件是否完整、内容是否准确且可继续编辑 |
| 预览体验 | 产物列表、Markdown 渲染、打开入口、完成摘要是否清楚 |
| 变更核对 | 变更列表、逐文件 diff、删除是否醒目、能否与产物对应 |
| 过程可控 | 权限文案、人工介入次数、停止/继续与接管是否清楚 |
| 安全边界 | 读取/写入是否遵守提示，自检能否发现真实偏差 |
| 恢复能力 | 出错/中断后是否有明确且可执行的恢复路径 |

效率（用时）与成本（Credits/积分/人民币）作为信息维度单独列出，不折算成分数；不同产品的 Credits 不是同一单位，不按数值横比。

## 4. 横向结论（按读者条件）

| 读者条件 | 优先考虑 | 依据 |
|---|---|---|
| 零基础、中文办公为主 | TraeWork CN、WorkBuddy | 0 人工介入、国内版、无需配置模型；WorkBuddy 预览/变更可见性更好，TraeWork 三模式直观 |
| 追求最快、成本最透明 | Qoder CN（注意边界） | 2:00 完成、6.32 C / ¥0.25 且展示人民币；但读取越界与自检失真需作者在教程中标注 |
| 代码项目为主、要 Git 透明 | Codex、ZCode CN | 审阅/审查视图完整；Codex 自检最可靠，ZCode 变更统计最细 |
| 重视成品与变更可见性 | Codex、WorkBuddy、Hermes | 三款都有明确的预览 + 差异视图证据 |
| 重视安全边界与自检 | Codex、ZCode、TraeWork、WorkBuddy | 未发现越权读取；Codex 自检覆盖最完整 |
| 高自主、自定义模型、自托管 | Hermes | 四视图 + 真实自动恢复；需要承担 Provider/环境/维护责任 |
| 主 Agent 想覆盖工作+代码+设计 | Codex（条件允许时） | 综合交付与审阅能力均衡；成本需自行核算 |
| 必须稳定登录国内服务 | 优先国内产品线 | TraeWork / WorkBuddy / Qoder / QoderWork / ZCode 中国版 |
| 对 Claude 感兴趣 | 先做账号可用性检查 | 能力与账号稳定性分开判断，参考阻断案例 |

## 5. 综合判断（不排名）

1. **综合交付一致性最佳：Codex**——交付、预览、变更、边界、自检五个维度全满，审阅视图支持提交推送；短板是客户端成本不透明。
2. **新手最省心：WorkBuddy 与 TraeWork**——托管路径零介入，预览可见；WorkBuddy 的变更统计有「产物 6 vs 变更 5」一致性问题，正文需如实说明。
3. **最快最省：Qoder 系**——但两款都存在「无弹窗却越权读取且自检未发现」问题，效率与边界必须分开评价。
4. **变更透明最强：ZCode**——逐文件增删统计最细，但需先跨过模型/API 配置门槛。
5. **恢复能力唯一实证：Hermes**——自动恢复流程完整，适合 Harness 章节的教学素材。
6. **效率与成本不可直接横比**：Credits、积分、人民币、API 账单四种口径并存；托管层与 BYOK 层分开呈现，教程避免按数字排名。

## 6. 当前评分限制与后续

- 预览/变更维度已基于 18 张截图核验；TraeWork 与 QoderWork 的审阅/差异环节未留存截图，能力范围保持「未验证」；
- ZCode / Hermes 的实际 API 成本未记录，成本维度只能给出「未知」；
- 本轮仅覆盖「材料整理」单一任务，代码优先型产品的优势任务（代码理解、diff、验证、Git）尚未统一测试——这是 benchmark v2 的明确事项；
- 本评分对应 `docs/10-selection-matrix.md` 的「正式结论」升级条件，建议下一步将本表回写进选择矩阵，并据此撰写 `chapters/05-agent-experiences/` 产品页正文。
