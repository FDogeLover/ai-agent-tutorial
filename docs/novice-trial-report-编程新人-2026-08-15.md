## 二、读不懂清单（按严重程度排序）

### A. 完全看不懂（影响我对整本书的定位理解）

1. **【序章 + 第 2 步画像 + 第 22 章案例】整本书到底支不支持"用 Agent 写代码"？三处信号打架**
   - 原文（序章 · 常见错误表）："| 任务选得太难（如「做个 App」） | 高估了自己当前的基础 | 拆小：先做「用 AI 整理一份需求文档」 |"
   - 原文（第 6 章 · 决策路径第 2 步）："| 代码项目为主，能接受 IDE | **Qoder CN、ZCode CN** | Codex |"
   - 原文（第 22 章案例摘要）："使用者基础：能完成第 7–18 章学习（不要求编程，但要求按步骤操作）"
   - 我的困惑：序章把我最想干的事（做个 App）直接列为"常见错误"，说这是"高估了自己当前的基础"；可第 6 章又专门给"代码项目为主"的读者推荐了三款产品；第 22 章还给了"软件与项目搭建"案例。所以——这套教程到底是"教我不碰代码"，还是"教我用 AI 碰代码"？像我这种正在学 Python、想拿 AI 帮我写练手项目的人，正确姿势到底是什么？全书没有任何一处正面回答。我现在的感觉是：方法论好像通用，但例子全是整理文档、写周报、选净水器，我套不到"写代码"上；而唯一接近的第 22 章，讲的又是建仓库、不是写代码。

2. **【第 5 章 ZCode 页】指引我去看一个不存在的内容**
   - 原文（ZCode 页 · 零基础提示）："零基础建议先看教程第 2 章「模型/API」概念再试"
   - 我的困惑：我翻回第 2 章找"模型/API"这一节，从头到尾没有——第 2 章讲的是能做什么/风险/委派等级。我猜它想让我看的是别的章【我猜的】，但我猜不出是哪章。这种"指路牌指了个空"比不指路还难受。

### B. 半懂（我猜了个解释继续读，不保证对——这部分请作者重点看）

3. **【第 2 章 → 第 5 章】Token：我一路都以为是"密钥"**
   - 原文（第 2 章 · 安全提醒）："不要在任务描述里粘贴真实密码、Token、身份证号"
   - 原文（第 5 章 Claude 页）："官方 API 是否另行计费：是，按 Token 单独计费"
   - 原文（第 5 章 ZCode 页）："首次使用 5 天体验：每日 GLM-5.2 300 万 Token + GLM-5-Turbo 200 万 Token（合计 500 万 Token/天）"
   - 我的误读过程（如实交代）：第 2 章看到 Token 和密码、身份证号排在一起，我脑补"Token 就是那种 API 密钥，sk- 开头的"，完全没停。到第 5 章 Claude 页"按 Token 单独计费"我还在圆："按密钥数量计费？不对吧……"直到 ZCode 页"每日 500 万 Token"我实在圆不下去了——密钥怎么论万个？这时我才回头翻，发现全书没有一处解释 Token 是什么。我现在的猜测是"用量单位，像流量按 MB 算"【我猜的】。但一个词让我错了三章才发现，要是没看到"500 万"那个数字，我会一直错下去。

4. **【第 2 章 + 第 8 章】两套 L 等级，我读成了一个体系**
   - 原文（第 2 章 · 委派等级）："**L1 全自动**：规则明确、材料齐、风险低 → 可以直接交"
   - 原文（第 8 章 · 权限分级）："**L1 写入（限定目录）**：在指定目录创建/修改文件"
   - 我的误读过程：第 8 章出现 L0–L3 时我一点没停，因为我"认识" L1——第 2 章学过嘛。我把两者焊在一起理解成："L1 全自动 = 它可以写文件，L0 = 只能看"。写这份报告回看原文才发现：第 2 章的 L1 是"放不放手"，第 8 章的 L1 是"给什么权限"，两套编号互不相干。也就是说我第 8、9、10 章关于等级的内容全部是带歪理解读下来的，自己毫无察觉。这大概就是试读说明里说我这类人的毛病——我以为我最不会出问题的地方，恰恰全错了。

5. **【第 5 章 Codex 页】"拉取请求（Pull Request）"与"Worktree"**
   - 原文："审阅视图可逐文件核对 diff，支持暂存/丢弃/提交，也支持拉取请求（Pull Request）"
   - 原文（问题记录）："文件提交后在 Worktree 中构建静态站点，发现指向旧版本的链接"
   - 我的理解【我猜的】：拉取请求 = 从 GitHub 上拉代码的请求？Worktree = 工作目录的英文叫法？我是硬猜的。我听过 GitHub，视频里讲师敲过 `git pull`，所以"拉取"我认识，但"拉取请求"是个请求就把我绕晕了——是我请求拉，还是我发请求让别人拉？这种词教程不解释，我这种"听过但没用过 GitHub"的人就是半懂装懂。

6. **【第 4 章】"环境配置"与 BYOK 的实操空白**
   - 原文（第 4 章 · BYOK）："BYOK（自带密钥）：在 Agent 里填自己的 API Key，由模型供应商直接计费。白话解释：不买产品套餐，自己租「模型算力」插进去。"
   - 原文（需求卡第 6 问）："能否处理 API Key、模型供应商和环境配置？"
   - 我的困惑：BYOK 的白话解释我读懂了，API Key 我也自认为认识（sk- 开头那种【我猜的】）。但"在哪里能弄到 API Key""要不要先去某个网站注册充值""环境配置是指像 pip 装依赖那种事吗"——教程一个字没有。我这种"会照抄 pip install"的人，恰恰是最容易被 BYOK 吸引（觉得能省钱）又最容易在配置上翻车的人，第 4 章到第 6 章都没有给一个"BYOK 第一步做什么"的说明。

7. **【第 22 章 · 出现的问题】git 相关的灾难描述，我一个字都不懂**
   - 原文："git 状态被干扰：开发环境后台的 Git 集成反复重置本地分支引用，常规提交失败 → 改用「提交哈希直推」方式绕过（提交对象始终安全）"
   - 原文（修正与判断）："发布流程：成块合并（squash PR），main 保持可发布状态。"
   - 我的困惑："本地分支引用""提交哈希直推""squash PR"——这是我全书唯一一段真的读不下去的文字。我是冲着"软件与项目搭建"标题点进来的，读完案例摘要我满怀期待，到"出现的问题"这一节彻底懵了。我意识到这章不是写给我这个层次的"软件爱好者"的，是写给已经会 git 的人的。可它是四选一的案例章里唯一和"写东西"沾边的，我退出后就没有别的可看了。

### C. 似懂非懂

8. **【第 23 章】Skill**
   - 原文（第 3 周表格）："D18 | 读第 13 章，把最高频任务做成最小 Skill | 第一个 Skill"
   - 我的理解【我猜的】：Skill = 插件？还是保存起来的常用指令？第 13 章在路线 A 之外我没读，第 23 章的表格让我下周就要做 Skill，我却不知道它是什么。对零基础读者来说，"第 23 章 = 全书收尾"，第一次听到 Skill 这个词是在收尾章，多少有点晚。

9. **【第 5 章 WorkBuddy 页】Coding Plan**

   - 我的理解【我猜的】：看名字 Coding Plan 是给写代码的人的订阅？那我是不是该买这个？没展开讲，我也不知道两类差别。对一个想转行的人，"哪个订阅适合学代码"是真金白银的问题，此处只有一行。

10. **【第 6 章 · 决策路径】"一图流"排版**

    - 我的困惑：四步内容我都单独读懂了，但这个总览图在网页上排版挤在一起，竖线和箭头错位。我这种读得快的人会扫一眼就放弃它，反正上面的表格更清楚。

11. **【第 5 章 TraeWork 页】"D6–D9"**

## 三、卡住与劝退点

1. **第 22 章案例是给我希望又让我摔得最重的一章。** 作为想转行的人，我在首页看到案例篇里有"软件与项目搭建"，直接把它当成这本书对我的招呼。结果前置要求是"能完成第 7–18 章学习"（路线 A 我只读了 1–10），内容核心是仓库和版本管理，术语（分支引用、squash PR、提交树）完全超出我。我的结论是"这章不是给我的"，但它是案例篇里唯一沾'软件'边的——那这本书里就没有给我的案例了。这是全书离我心态崩掉最近的一次。
2. **"先看第 2 章模型/API 概念"的空指路让我翻书白跑一趟**（见读不懂清单 2）。指引类文字指错位置，对我这种"听话照做"的读者杀伤力最大。
3. **Token 和两套 L 等级的"假读懂"。** 我读的时候全程顺畅、零卡顿——问题恰恰在这。错误理解是写出这份报告、重新对照原文时才暴露的。真实阅读场景里不会有"写报告复盘"这个环节，我就会带着"L1=全自动=可写文件"的错误理解去实际操作产品。
4. **第 5 章我对 Codex 页最上头，但我不知道拿它怎么办。** 页面说它"审阅支持提交推送""拉取请求"，我看着很心动，可我连 GitHub 账号都没有。从"心动"到"我该去注册 GitHub 吗、注册了干什么、和教程什么关系"，中间没有任何台阶。我卡在这页想了十分钟"我到底要不要为了用 Agent 先去学 git"。

## 五、改进建议（作为"想转行编程"的读者）

### P0

1. **请正面回答"想用 AI 写代码的人怎么用这本书"**。我的建议：在序章或第 2 章加一小节，明说类似"本书教的是把任务交给 Agent 的方法，写代码任务同样适用；但「让 Agent 从零做一个 App」对新手是高风险任务（为什么），建议从 X 开始"。现在序章只丢下一句"任务选得太难（如「做个 App」）"就走了，我读完的感觉是被判了刑又没人告诉我刑期怎么算。
2. **修复 ZCode 页"先看第 2 章「模型/API」概念"的空指引**——要么把它指向真实存在的章节，要么在所指处补上内容。
3. **Token 加首次解释**。别让"半懂型"读者像我一样把它当密钥理解三章。一句"Token 是模型计费用的用量单位"就够，放在第 2 章安全提醒第一次出现处。
4. **两套 L 等级（第 2 章委派 L1–L4、第 8 章权限 L0–L3）换掉其中一套的编号**。我这种读者不会发现自己混了，只会把错误理解带进实操。
