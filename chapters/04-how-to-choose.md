# 第 4 章：不背产品参数，先看选择维度

> 页面标识：ch-04-how-to-choose
>
> 摘要：四组入门分类 + 六个辅助维度，教你用「需求卡」而非产品参数来选 Agent；账号稳定性是前置门槛。
>
> 适合人群：所有人｜难度：入门｜阅读时间：约 20 分钟
>
> 创建日期：2026-08-13｜最后核验：2026-08-13｜标签：选型、第一篇

## 本章解决什么问题

打开任何一款 Agent 的官网，你都会看到一堆参数：上下文长度、模型名称、Credits、套餐价格……**零基础用户背这些毫无意义**——因为参数不等于体验。本章教你反过来：先搞清楚**你自己的需求**，再拿需求去匹配产品。产出：一张**个人 Agent 需求卡**。第 5、6 章会拿这张卡直接去七款产品里选。

## 从一个真实场景开始

我的一个朋友想买「最强」的 AI 产品，对比了一晚上参数表，最后因为「模型分数最高」选了一款海外产品。结果：注册需要海外支付方式，折腾两天没付成款，弃用。

另一个朋友选了参数表上「没那么亮眼」的国内产品，半小时跑通了第一个任务，现在每天都在用。

**参数不会告诉你「你能不能注册」「界面你顺不顺手」「它会不会偷偷读你的文件」。** 这些才是新手真正要看的维度。

## 先说结论

1. **先分四组建立直觉**：海外综合型（Claude、Codex）、国内综合型（TraeWork、WorkBuddy）、代码优先型（Qoder、ZCode）、开源自主型（Hermes）。分组帮新手建立第一印象，**不是能力排名**；
2. **再用六个维度交叉判断**：任务方向、开放程度、运行方式、自主程度、使用门槛、账号与地区稳定性；
3. **账号与地区稳定性是前置门槛**：能力再强，注册不了、付不了款、账号被封，都是零（第 5 章 Claude 页就是活案例）；
4. **价格是最后看的**，而且要看「单位、重置规则、活动期限」，不是只看「每月多少钱」；
5. **七款产品的实测结论见第 5、6 章**——本章给你「需求卡」，下一章给你「产品证据」，第 6 章教你「怎么选」。

## 必要概念

- **四组分类**（来自仓库 `docs/06-agent-taxonomy.md`，仓库内部文档、站内打不开；选型辅助而非排名）：

| 分组 | 代表产品 | 看什么 |
|---|---|---|
| 海外闭源托管型综合 Agent | Claude、Codex | 综合能力、官方托管、服务边界 |
| 国内综合型 Agent | TraeWork 中国版、WorkBuddy | 中文、本地化、上手便利 |
| 代码优先型 Agent | Qoder 中国版、ZCode 中国版 | 项目理解、代码修改、验证 |
| 开源自主型 Agent | Hermes Desktop | 自由度、可定制、维护责任 |

- **六个辅助维度**：任务方向（办公/代码/设计/研究）、开放程度（源码/接口/模型开放度）、运行方式（云端/本地/自托管）、自主程度（每步确认 vs 连续执行）、使用门槛（零基础 GUI 可否）、账号与服务稳定性（能否注册、付费、申诉）。
- **BYOK（自带密钥）**：在 Agent 里填自己的 API Key，由模型供应商直接计费。白话解释：不买产品套餐，自己租「模型算力」插进去。它带来自由，也带来配置与账单管理成本。

## 跟着做：制作你的需求卡

### 第一步：回答八个问题

| # | 问题 | 我的答案 |
|---|---|---|
| 1 | 我的三个主要任务是什么？（从序章任务延伸） | |
| 2 | 必须支持的文件或工具？ | |
| 3 | 我所在地区、可用支付方式？ | |
| 4 | 能接受的月度预算？ | |
| 5 | 能否接受云端处理资料？ | |
| 6 | 能否处理 API Key、模型供应商和环境配置？ | |
| 7 | 账号中断时允许损失多少历史记录和时间？ | |
| 8 | 我更看重：省心 / 便宜 / 透明 / 自由？（选两个） | |

### 第二步：把答案翻译成「筛选条件」

- 第 3 题答「只有国内支付」→ 排除海外付费产品；
- 第 5 题答「不能接受资料出境」→ 排除海外托管产品；
- 第 6 题答「不想碰 API」→ 排除 BYOK 主推产品（ZCode、Hermes 默认路径）；
- 第 7 题答「账号不能出事」→ 把账号稳定性列为硬条件；
- 第 8 题决定你最终比较时最看重哪两个维度（如「省心 + 透明」）。

### 第三步：写下候选清单

先不追求精确，写下 2–4 款你觉得符合的候选，**带着需求卡去读第 5 章对应产品页和第 6 章选择表**。

## 一个完整示例

我的需求卡（可对照第 6 章个人选型结论页）：

- 主要任务：教程写作（文档）、代码项目、跨工具资料整理 → 综合型 + 代码型都要考虑；
- 支付：国内支付为主 → 国内产品优先，海外产品需评估；
- 预算：中，可订阅但不接受不可控成本；
- 资料边界：可云端，但重视「是否越权读取」；
- 配置能力：能配 API → BYOK 不排除，但优先级靠后；
- 最看重：省心 + 透明（变更可核对）。

筛选结果：WorkBuddy、Codex 进入主候选（对应第 6 章结论）。注意：**我的权重是「边界安全 + 变更透明」，如果你的权重是「最快最省」，结论会不同**——这正是需求卡存在的意义。

## 常见错误与恢复方法

| 现象 | 可能原因 | 怎样修正 |
|---|---|---|
| 按模型分数选产品 | 把模型能力当产品能力 | 回到六个维度；模型只是五块拼图之一 |
| 看参数表比较上下文长度 | 参数 ≠ 体验 | 实测里没人量上下文，量的是「任务能不能一次过」 |
| 被「新用户福利」吸引注册 | 没看活动期限与适用产品线 | 对照仓库 `docs/07`（仓库内部文档、站内打不开）：很多福利已截止或属于别的产品线 |
| 海外产品付不了款 | 没先查支付方式 | 需求卡第 3 题先答，别等注册时才发现 |
| 账号被封才想起风险 | 没做前置检查 | 把「账号与地区稳定性」列为硬门槛（第 5 章 Claude 页） |

## 安全提醒

- 注册任何产品前，确认它处理你资料的**数据政策**与你的组织/公司合规要求；
- 不要把公司机密、客户数据放进未获授权的工具；
- 「免费」最贵：看清免费额度的单位、重置周期、模型限制与活动期限（仓库 `docs/07` 有逐款核验表，站内打不开，核验要点已在本页安全提醒中）。

## 本章练习

20 分钟：完成需求卡八问 → 翻译成筛选条件 → 写下 2–4 款候选 → 去第 5 章对应页面读「一句话结论」和「适合与不适合」，验证你的候选是否成立。

## 你应该带走的成果

- **个人 Agent 需求卡**：八问答案 + 筛选条件 + 候选清单（这是第 6 章选择路径的输入）。

## 本章小结

1. 四组分类建立直觉，不排名；
2. 六个维度交叉判断，需求卡是工具；
3. 账号与地区稳定性是前置门槛；
4. 价格看单位、重置与期限，不只看金额；
5. 需求卡 + 第 5 章证据 + 第 6 章路径 = 你的选择。
