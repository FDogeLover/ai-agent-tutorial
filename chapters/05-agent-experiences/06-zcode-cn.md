## 1. 一句话结论

**变更透明性最强的产品**：审查视图提供逐文件增删统计（+46、+37、+84 等），每一份输入/输出/验收文件的改动都可逐项核对，Git 与任务管理深度整合。代价是门槛：本轮为 BYOK 配置（OpenCode Go + DeepSeek V4 Flash + 最高推理），需要理解模型/API/推理强度概念，新手要先跨过配置门槛。

## 7. 三类实测任务

### 7.1 共同基准任务（2026-08-12）

#### 任务背景

使用冻结的教程材料包（`input/` 7 份文件），整理 AI Agent 教程材料，生成六个指定交付文件并自检。

#### 完整输入

冻结材料包 + `zcode-prompt.md` 统一提示。

#### 执行过程

打开 ZCode → 新建任务并选择运行目录 → 不执行配置助手或初始化 → 保持默认权限、模型与推理（BYOK：OpenCode Go / DeepSeek V4 Flash / 最高）→ 粘贴统一提示发送；执行中按「变更前确认」批准写入并回复继续。

#### 最终结果

六份指定文件按顺序生成（08:38:16 首文件至 08:40:42 末文件），总用时 5 分 41 秒（测试者记录；首末文件间隔 2 分 26 秒）。

#### 验收情况

- 交付：6/6 一次完成，无中断/报错/重试；7/7 输入 SHA-256 与基线一致；权限确认与人工回复各 ≥1 次（精确次数未记录）；
- 内容亮点：材料边界处理较好（明确声明目录是重建提案）；写作计划 P0-P2、依赖链、阻塞项完整；待办九组复选框分层清楚；未发现读取 input 之外文件；
- 内容偏差：自行生成第 0–11 部分目录（声明为需合并的提案）；**自检漏列第 7 个输入文件 `OUTPUT-REQUIREMENTS.md`**，且未反映真实权限确认过程；
- 指标：澄清/人工回复 ≥1 次；权限确认 ≥1 次；中断 0 / 报错 0 / 重试 0 / 恢复 0。

| 指标 | 记录 |

| 问题 | 出现条件 | 对结果的影响 | 恢复步骤 | 新手能否独立处理 |
|---|---|---|---|---|
| 默认任务需自行选择模型渠道 | 3.7.6 未观察到统一 Auto 模式 | 新手需理解 API/模型/推理强度；结果与成本受供应商影响 | 明确记录 BYOK 组合，不与默认 Auto 混评 | 无基础的新手可能需要额外指导 |

| 自检不完整 | 漏列第 7 个输入文件、未反映权限确认 | 只看自检会低估实际介入 | 以人工验收与运行记录为准 | 需要教程示范独立核验 |

## 9. 适合与不适合

### 更适合

- 需要 Git 级变更透明的代码用户（逐文件增删统计可逐项核对）；
- 愿意配置模型与 API、重视写入可控性（变更前确认）的用户；
- 有编程或系统配置经验的用户。

### 可能不适合

- 零基础新手（模型/API/推理概念门槛高）；
- 想要「打开就用」托管体验的用户（无统一 Auto 模式）；
- 希望客户端内直接看到成本费用的用户（BYOK 成本需另查供应商账单）。

## 10. 最终结论

- 是否推荐新手试用：**有条件推荐**——有配置基础者可先体验 5 天新手额度；纯零基础建议先看教程第 2 章「模型/API」概念再试；
- 什么条件下值得购买官方订阅：代码任务量大且需要完整变更审阅时，GLM Coding Plan 按档位选择；BYOK 用户按供应商用量评估；
- 最适合作为主 Agent、辅助 Agent 还是专用工具：**代码/项目型主 Agent 候选**（变更透明性最高）；
- 与相邻产品的差异：与 Qoder 同属代码优先型，ZCode 是 BYOK 路径（变更统计最细、写入需批准），Qoder 是托管 Auto 路径（最快最省但边界失分）；与 Codex 相比，ZCode 变更统计更细但配置门槛更高，Codex 托管订阅开箱即用；
- 仍需要后续版本继续核验：统一 Auto 模式是否提供、精确权限确认次数、代码优势任务、外部成本核算。
