# 第 3 章：人与 Agent 怎样分工

> 页面标识：ch-03-human-agent-division

> 摘要：人负责目标、取舍、授权与最终责任；Agent 负责检索、整理、生成、执行与重复劳动；监督强度随风险变化。
>
> 适合人群：所有人｜难度：入门｜阅读时间：约 15 分钟
>
> 创建日期：2026-08-13｜最后核验：2026-08-13｜标签：分工、责任、协作

## 本章解决什么问题

前两章讲了 Agent 是什么、能做什么。本章回答一个更实际的问题：**一件事到底该谁做？** 用得好的用户不是「把所有事丢给 Agent」，而是有一套稳定的分工原则——知道哪些永远自己定、哪些大胆放手、哪些盯紧一点。本章产出**个人的人机分工表**。

## 从一个真实场景开始

一位同事让我帮他优化一份给领导的汇报。他把几十页原始材料丢给 Agent，说「帮我总结一下」，然后原样把总结发出去。结果汇报里出现了 Agent 编造的数据——他事后抱怨「AI 太不靠谱」。

问题不在 Agent。问题在于：**他把「取舍」也交给了 Agent**——哪些数据重要、什么口径、给谁看，这些是人的判断，Agent 不可能替他负责。同样一份材料，如果他把「口径」定清楚，Agent 的总结会很可靠。

## 先说结论

1. **四件事永远是人来定**：目标（做什么、为什么）、取舍（哪个更重要）、授权（允许做什么）、责任（出了问题谁承担）；
2. **四件事可以放手给 Agent**：检索（找材料）、整理（分类、汇总）、生成（初稿、格式）、执行（按规则做事、重复劳动）；
3. **监督强度随风险变化**：风险越低越放手，越高越盯紧——不是「要么全自动，要么全手动」；
4. **好的协作是「人定框架，Agent 填内容，人验收」**，而不是「人出题，Agent 全包」。

## 必要概念

- **授权（Authorization）**：你明确允许 Agent 做的事的范围。没有授权的行为，哪怕 Agent 自己觉得「顺手做了」，也是越权。
- **责任（Accountability）**：最终对结果负责的是人，不是工具。白话解释：实习生办砸了，领导担责的是你。
- **监督强度（Supervision level）**：你介入检查的频率与深度。它与风险成正比：层级 1 低风险任务可以不打扰地跑完，层级 4 高风险任务每一步都要确认。

## 人与 Agent 的分工表

| 环节 | 谁负责 | 具体内容 | 理由 |
|---|---|---|---|
| 定目标 | **人** | 要达成什么、做到什么程度 | 价值判断，Agent 无法替你定义「好」 |
| 定口径/取舍 | **人** | 哪些因素重要、冲突时优先什么 | 依赖你的场景与偏好 |
| 备材料 | 人 + Agent | 人提供入口，Agent 帮助检索/整理 | 上下文决定质量（第 11 章） |
| 定边界 | **人** | 允许读什么、写什么、能否联网 | 授权是你的责任 |
| 规划步骤 | Agent | 拆解步骤、排序 | 这正是 Agent 的强项，但你要能看懂计划 |
| 执行 | Agent | 读写文件、生成内容、调用工具 | 重复劳动交给机器 |
| 过程监督 | 人（按需） | 分段确认、看日志、叫停 | 强度随风险（第 9 章） |
| 验收 | **人** | 对照标准逐项检查、独立核验 | 结果可信度由人把关（第 10 章） |
| 最终责任 | **人** | 发布、提交、付款等动作的拍板 | 法律与后果由人承担 |

## 跟着做：建立你的分工表

### 第一步：列出你任务里的所有环节

把序章的任务种子拆成环节（从「收集材料」到「最终交付」）。

### 第二步：对照分工表，给每环节标「人 / Agent / 人+Agent」

诚实一点：标「人」的，是你真的会亲自做的，而不是「反正 Agent 会做」的。

### 第三步：标出「必须人工确认点」

在涉及以下动作的环节画 ❗：对外发送、发布、付款、删除、修改重要文件、提供个人信息。这些是硬确认点，第 8 章会展开成权限分级表。

### 第四步：为你的任务定「监督档位」

结合第 2 章的委派等级，写一句监督策略，例如：

> 「材料整理（层级 1）：全程自动，交付后核验边界；最终对外发送（层级 4）：人来做。」

## 一个完整示例

回到我写这本书的真实分工（可对照第 5、6 章的产出过程）：

| 环节 | 负责人 | 实际做法 |
|---|---|---|
| 定教程框架与边界 | 人 | 23 章目录、读者画像、内容边界（仓库 `docs/00-06`，站内打不开） |
| 七款产品实测 | Agent + 人 | Agent 执行统一基准任务；人记录介入/用时/成本（`research/runs/`） |
| 截图分析 | Agent | 视觉模型逐张分析 18 张截图；人审核描述 |
| 界面讲解/产品页写作 | Agent + 人 | Agent 起草十段式正文；人核对事实、标注「未验证」 |
| 横评评分 | 人 | 六维评分与结论由人依据证据卡给出（仓库 `docs/12`，站内打不开） |
| 选择结论 | **人** | 「适合谁」的结论由人下，Agent 只提供证据 |
| 发布决策 | **人** | 何时合并、何时发布，全部人工确认 |

这个例子说明：**Agent 承担了绝大部分「生成」工作，但框架、取舍、评分、发布这些环节始终是人的。** 这也正是这套教程能保持可信的原因。

## 常见错误与恢复方法

| 现象 | 可能原因 | 怎样修正 |
|---|---|---|
| 「帮我总结一下」原样发出 | 把取舍交给了 Agent | 先自己定口径，再让 Agent 按口径总结 |
| 全程不监督，出事后怪 AI | 监督档位没设 | 按风险设档，层级 2 以上分段确认 |
| 每步都打断，Agent 没法干活 | 监督过度 | 低风险环节设成「完成后汇报」，别事事等确认 |
| 边界没写，Agent 越权 | 授权不清 | 任务卡写清范围与禁区（第 7 章） |
| 让 Agent 替自己做决定 | 责任错位 | 决策留给自己，让 Agent 提供选项与依据 |

## 安全提醒

- 你签发的授权，后果由你承担：**不要在没想清楚的情况下放开「全权」**；
- 对外发布类动作永远是人的动作，即使内容 90% 是 Agent 生成的；
- 涉及医疗、法律、财务：Agent 只出草稿，最终判断必须专业人士。

## 本章小结

1. 目标、取舍、授权、责任四件事永远是人的；
2. 检索、整理、生成、执行四件事可以放手；
3. 监督强度随风险变化，不是非黑即白；
4. 好的协作：人定框架，Agent 填内容，人验收；
5. 你已拥有分工表，下一步（第 4 章）选工具。
