# 第 1 章：AI Agent 到底是什么

> 页面标识：ch-01-what-is-an-agent
>
> 摘要：用生活化比喻讲清普通聊天、Copilot 与 Agent 的区别，以及模型、上下文、工具、记忆与权限五个基本概念。
>
> 适合人群：所有人｜难度：入门｜阅读时间：约 15 分钟

## 本章解决什么问题

你天天听人说「AI Agent」，但可能说不清它和 ChatGPT 聊天框有什么区别。本章用一个贯穿全书的比喻讲清**模型、上下文、工具、记忆、权限**五个概念，并让你画出一张 **Agent 工作流程图**——为什么「会聊天」不等于「会干活」。

## 从一个真实场景开始

你让聊天 AI「帮我整理旅行照片」。它回复：「你可以先按日期分类，再删除模糊的……祝旅途愉快！」——给了你一篇攻略，照片一张没动。

同样一句话对桌面 Agent 说，它可能：打开照片文件夹 → 按日期和地点分组 → 把重复照片挑到「待删除」→ 生成相册目录 → 告诉你「共整理 214 张，重复 37 张」。

**两者都能「回答」，只有后者「干活」。** 差别就在本章。

## 先说结论

1. **Agent 的本质是「能执行任务的 AI」**——自己规划步骤、调用工具、读写文件，并对结果负责；
2. **Agent 由五块拼图组成**：模型（思考的脑子）、上下文（眼前能看到什么）、工具（能动手做什么）、记忆（长期记得什么）、权限（被允许做什么）；
3. **模型能力不是 Agent 的全部**：同样的模型放在不同 Agent 里体验完全不同——工具、权限和验证流程是产品自己搭的（第 5 章实测反复证明）；
4. **Agent 也会犯错，且形态与聊天 AI 不同**：可能读错文件、改错地方、或「自信地」做了你没让它做的事——知道它由什么组成，才知道该检查哪里（第 2、8、10 章展开）。

## 必要概念（用一个比喻）

把 Agent 想象成**一位新入职的实习生**：

| 概念 | 白话解释 | 实习生比喻 |
|---|---|---|
| **模型** | Agent 用来思考和生成内容的 AI 大脑 | 实习生的「能力水平」 |
| **上下文** | 这次任务里它能「看到」的全部信息：你的话、文件、规则 | 实习生眼前摊开的资料和口头交代 |
| **工具** | 它实际能调用的能力：读文件、写文件、跑计算、访问网页 | 实习生能用的电脑、打印机、电话 |
| **记忆** | 跨任务记住的长期信息：你的偏好、历史约定 | 实习生的笔记本 |
| **权限** | 它被允许做的事的范围 | 实习生的门禁卡和「需经理审批」的规定 |

- **模型**：白话理解「一个根据你输入的内容，预测并生成下一步文字的巨型程序」。正式说法：通过大规模训练学会理解和生成自然语言等内容的神经网络。它决定 Agent「想得到想不到」，不决定它「做得到做不到」。
- **上下文**：本次任务 Agent 能看到的全部信息。它不能像人一样「凭记忆」——没放进上下文的信息，对它等于不存在。
- **工具**：Agent 主动调用的外部能力（文件读写、命令行、浏览器、表格）。有工具的 Agent 才能从「说话」变成「干活」。
- **记忆**：产品的长期存储（规则、偏好、历史），通常做成可编辑的文件或设置项。
- **权限**：产品对 Agent 行为的限制规则——能否写文件、能否联网、哪些操作需要你确认。

## 三种形态，三个台阶

| 形态 | 例子 | 会做什么 | 不会做什么 |
|---|---|---|---|
| 聊天 AI | ChatGPT 网页聊天 | 生成回答、写文案、问答 | 自己动你的文件、替你执行 |
| Copilot | 编辑器补全助手 | 在你操作时给建议、补全 | 独立完成多步骤任务 |
| Agent | 桌面 Agent（第 5 章七款） | 接收任务、规划、调工具、交付结果 | 替你承担最终责任（责任仍在人，第 3 章） |

**不是越高级越好，而是匹配任务**：查事实用聊天 AI 最快；写代码 Copilot 顺手；「把一摊材料整理成六个文档」这种多步骤任务才值得动用 Agent。

## 跟着做：画一张 Agent 工作流程图

以序章的任务种子为例，在纸上画出 Agent 处理它的过程：

1. **输入（人 → Agent）**：左侧画人，箭头指向 Agent，旁边写：目标、材料、约束、验收标准；
2. **内部三段循环**：Agent 框内画 理解（读目标+上下文）→ 行动（调工具）→ 反馈（观察结果）→ 回到理解，用循环箭头连起来；
3. **交付（Agent → 人）**：右侧再画你，输出箭头旁写：成品、过程记录、自检说明；旁边写「我检查，我负责」；
4. **对照产品找五块拼图**：打开已装的桌面 Agent（没有就跳过，第 4 章会选），找模型/模式（设置或对话上方）、上下文（`@文件` 引用、任务描述）、工具（读文件/写文件等动作）、记忆（规则/偏好/项目配置）、权限（权限模式/需确认操作）。

## 一个完整示例

实测场景（第 5 章 WorkBuddy 页有完整记录）：任务「整理教程材料，生成六份指定文档」+ 材料包 7 个文件 + 约束（只读 `input`、输出到 `output`）+ 验收标准。流程：理解 → 读取材料逐份生成 6 份文档 → 自检发现材料边界偏差（把裁剪输入外内容列为缺失）→ 停止并说明 → 人复核发现「产物 6 份 vs 变更列表 5 份」的展示问题，以文件系统为准验收。

这个例子说明：**每一步都可能出问题，而检查点（反馈 → 人复核）才是流程闭环的关键。**

## 常见错误与恢复方法

| 现象 | 可能原因 | 怎样修正 |
|---|---|---|
| 以为模型强 = Agent 好用 | 把模型能力等同于产品能力 | 对照第 5 章：同样的 DeepSeek V4 Flash，不同产品体验不同 |
| 把聊天 AI 的对话习惯用在 Agent 上 | 没意识到 Agent 会「动手」 | 先想清楚：这次任务要不要它碰我的文件？ |
| 找不到「记忆」在哪里 | 产品术语不同（规则/偏好/项目配置） | 看产品文档或帮助入口 |
| 画图时发现「权限」没概念 | 还没用过会写文件的 Agent | 先读第 8 章再回来画 |

## 安全提醒

- 让 Agent 动手的第一原则：**先给只读权限或临时目录**，确认它能正确理解范围后再放开（第 8 章系统讲解）；
- 任务种子暂时不要包含账号密码、身份证号等敏感信息。

## 本章小结

1. Agent 与聊天 AI 的根本区别：执行任务，而不只是生成回答；
2. Agent = 模型 + 上下文 + 工具 + 记忆 + 权限；
3. 聊天 / Copilot / Agent 三个台阶，匹配任务才重要；
4. Agent 的工作是「理解 → 行动 → 反馈」循环；
5. 反馈与人的检查，才是流程闭环的关键。
