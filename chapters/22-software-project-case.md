> 适合人群：中级—高级｜难度：中级｜阅读时间：约 30 分钟

## 案例摘要

- 使用场景：软件与项目搭建
- 使用者基础：能完成第 7–18 章（不要求编程）
- 使用的 Agent：桌面 Agent（Codex 等）+ 视觉模型
- 完成时间：约两周（跨多阶段）
- 风险等级：中（涉及 git、发布）
- 最终交付物：公开 GitHub 仓库（23 章 + 实测 + 截图 + 文档）

## 任务背景

内容规划好后（第 21 章），需「能放内容、能协作、能发布」的仓库，并把七款实测纳入管理：数据归档、截图规范、结论可回查。这是典型软件项目：**内容工程 + 数据归档 + 版本管理**。

## 原始需求

> 「建一个教程仓库，把章节、素材、实测数据都放进去，并且能管理好版本。」

## 任务判断

- 适合 Agent：目录/文件、批量整理、数据汇总；
- 交给 Agent：建骨架、批量格式化、基准执行、界面文档、评分整理；
- 人必须做：架构决策、每阶段验收、git、发布决策。

## 整理后的任务卡（阶段一：框架搭建）

- **目标**：23 章教程的仓库骨架；
- **上下文**：零基础读者；中国版用中国站资料；
- **输入材料**：规划文档（`docs/00-06`）；
- **范围与约束**：只创建不删除、按规划命名；
- **交付物**：仓库结构 + README + 规范文档；
- **验收标准**：目录与规划一致、职责明确。

## 执行过程（六个阶段）

1. **框架搭建**：仓库、23 章目录、规范（`docs/00-06`）、模板（`templates/`）；
2. **定价调研**：核对七款中国版价格与福利 → `docs/07`；
3. **本机界面核对**：安装版本、界面形态（`docs/09`）；
4. **基准实测**：统一任务（`docs/08`）→ 七款实测 → 归档（`research/runs/`）；
5. **截图与界面讲解**：18 张截图 → 视觉模型 → 7 份讲解（`docs/11-interface-guides/`）；
6. **评分与正文**：六维评分（`docs/12`）→ 产品页（第 5 章）→ 矩阵（`docs/10`）→ 第 6 章。

## 出现的问题（真实记录）

- **git 状态被干扰**：后台 Git 集成反复重置分支引用 → 「提交哈希直推」；
- **工作区文件被清理**：8 个文档消失 → 从 git 恢复；
- **提交树不完整**：一次构建缺大量文件 → 差异校验重建（第 18 章回归验证的实战）；
- **截图命名不统一**：草稿与规范冲突 → 统一更新；
- **文档链接失效**：引用路径错误 → 批量脚本修复。

## 修正与判断

- 版本管理：**内容先入 git 再继续**，任何阶段可回滚（第 8 章）；
- 证据归档：实测、截图、运行记录全部入库，结论可回查；
- 易变信息：价格/版本统一在 `docs/07`，正文不复制；
- 发布：成块合并（squash PR），main 可发布。

## 最终结果与验收

- 公开仓库：`FDogeLover/ai-agent-tutorial`（GitHub）；
- 内容：23 章目录 + 5、6 章完整正文 + 其余章节正文 + 实测数据 + 18 张截图 + 8 份界面文档 + 规范文档；
- 验收：每阶段按任务卡验收；发布前批量校验链接与事实分级。

## 复盘

- Agent 做得好：骨架搭建、批量整理、基准执行、界面文档、评分整理；
- 人必须介入：架构决策、每阶段验收、git 异常处置、发布决策；
- 可沉淀：**项目规则集**（`docs/03` + `docs/04` + 链接校验脚本）——第 16 章六层架构落地；
- 教训：**版本管理与备份是安全底线**（第 8 章「后悔药」）。

## 给新手的最小版本

40 分钟复现：为个人项目（如「家庭菜谱库」）建仓库：建目录 → 写 3 条规则 → 加 1 模板 → 生成 2 份 → 提交并验证「删了能恢复」。**关键不是代码，而是「规则 + 版本 + 验证」。**
