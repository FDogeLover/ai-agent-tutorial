# 附录 B：任务卡模板

> 页面标识：app-task-brief-template
>
> 摘要：可直接复制使用的空白任务卡（六要素 + 假想敌测试），配套填写说明与示例。
>
> 创建日期：2026-08-13｜最后核验：2026-08-13｜标签：附录、模板、任务卡

## 使用方法

1. 复制下方模板到新文件（建议命名 `tasks/任务名.md`）；
2. 按括号内说明填写；拿不准的字段参考「填写示例」；
3. 发任务前做一遍「假想敌测试」（见模板末尾）。

## 空白模板

```markdown
# 任务卡：【任务名称】

> 创建日期：【日期】｜发起人：【姓名】

## 1. 目标

【一句话：做什么 + 为谁做 + 做到什么程度】
（例：把 material/ 下 8 份产品材料整理成选型对比文档，供零基础读者 10 分钟读完。）

## 2. 上下文

【Agent 需要知道但材料里没有的背景：读者、用途、口径、术语约定】
（例：读者为零基础；价格口径只用人民币；不讨论模型原理，只记录产品体验。）

## 3. 输入材料

- 【文件或路径】——【作用】
- 【文件或路径】——【作用】
（说明：输入范围之外的内容视为「未提供」，不要推断。）

## 4. 范围与约束

- 读取范围：只读【目录/文件】
- 写入范围：输出到【目录】，不修改其他位置
- 联网：允许 / 禁止（选一，并说明）
- 禁区：
  - 【绝不能做的事 1】
  - 【绝不能做的事 2】

## 5. 交付物

- 【文件名.格式】——【内容说明】
- 【文件名.格式】——【内容说明】
（精确到文件名；可要求 Agent 先报交付清单再开始。）

## 6. 验收标准

- [ ] 【可逐项打勾的条件 1】（可数/可查/可证）
- [ ] 【可逐项打勾的条件 2】
- [ ] 【可逐项打勾的条件 3】

## 7. 权限卡（可选，高风险任务用）

| 权限项 | 允许 | 禁止 |
|---|---|---|
| 读取 | | |
| 写入 | | |
| 执行 | | |
| 外部操作 | | |
```

## 填写示例（来自第 5 章统一基准任务）

> 目标：整理 `input/` 下 7 份教程材料，输出 6 份指定文档，用于七款产品统一实测。
> 上下文：零基础读者；Qoder/TraeWork/ZCode 只用中国版资料。
> 材料：`input/` 7 份文件（简报、笔记、反馈、事实表、流程图、输出要求）。
> 约束：只读 `input/`；输出 `output/`；不联网；不修改输入；不把 Claude 封号原因写成事实。
> 交付物：01-project-summary.md 等 6 份。
> 验收：6 份齐全；按要求结构；区分事实/推断；自检含输入清单与边界。

## 假想敌测试（发任务前必做）

假想一个爱偷懒、爱猜的 Agent 读这张卡，回答：

- [ ] 它会不会不知道该不该联网？（→ 约束里写清）
- [ ] 它会不会不知道输出到哪？（→ 交付物写清目录与文件名）
- [ ] 它会不会漏做某一部分？（→ 交付清单 + 验收标准逐项列）
- [ ] 它会不会擅自扩大范围？（→ 读取/写入范围写死）
- [ ] 它会不会编数据？（→ 验收标准写「无虚构数据，来源标注」）

全部回答「不会」，这张卡才算合格。
