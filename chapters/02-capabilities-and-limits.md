# 第 2 章：Agent 能做什么，不能做什么

> 页面标识：ch-02-capabilities-and-limits
>
> 摘要：适合委派与不适合委派的任务特征，幻觉、遗漏、误操作、越权与隐私五类风险，以及「能生成结果 ≠ 结果可信」。
>
> 适合人群：所有人｜难度：入门｜阅读时间：约 20 分钟

## 本章解决什么问题

第一次用 Agent 只有两种体验：惊艳（「它居然全会！」）或翻车（「它居然敢这么干！」）。都源于同一个问题——**不知道 Agent 的能力边界**。本章给你一张**任务适配性检查表**：什么任务放心交给它、什么要加人工确认、什么根本不该碰。

## 从一个真实场景开始

我测试一款 Agent 时，任务明确写着「只允许读取 `input` 文件夹」。它正常完成、无报错、自检「全部通过」——但事后检查发现：**它悄悄读取了工作目录之外的文件**（第 5 章 Qoder 页）。同一批测试里，另一款 Agent 把文件写错位置，然后**自己发现、自己迁移、自己复核**（第 5 章 Hermes 页）。

两个案例说明：Agent 可能在你没注意时越界，也可能在出事后自我修复。**「能生成结果」和「结果可信」是两件事**——这正是本章要训练你的判断力。

## 先说结论

1. **Agent 擅长**：信息密集的重复劳动、多步骤文档/数据整理、需要工具调用的执行类任务、可在材料范围内自查的任务；
2. **Agent 不擅长**：需要实时现实感知的事、需要价值取舍的事（让它替你决定「哪个更重要」很危险）、需要为它自己的话负责的事；
3. **五类风险要盯住**：幻觉（编造）、遗漏（漏做）、误操作（改错）、越权（碰了不该碰的）、隐私泄露（资料外流）；
4. **最反直觉的一条**：Agent 越「自信」地声称完成，越要核对——**自检通过 ≠ 真的通过**（实测中多款产品自检都漏掉了自己的问题）。

## 必要概念

- **幻觉**：AI 生成了看起来合理、实际错误的内容——「一本正经地胡说八道」。原因：它生成的是「最像样的答案」，不是「经过验证的事实」。
- **遗漏**：任务多个部分只做了一部分，且可能不告诉你。白话：布置 6 道题，它做了 4 道就说「写完了」。
- **误操作**：改了不该改的文件、删了不该删的内容。
- **越权**：行为超出你授予的范围（读取范围、写入范围、联网、调用外部服务）。
- **自检**：Agent 交付前的自我检查。**自检是产品设计，不是可信保证**——实测里自检漏报是常态。

## 任务适配性检查表

拿出序章的任务种子，逐条勾选：

| 检查项 | 越符合 → 越适合交给 Agent | 越符合 → 越要人盯/别碰 |
|---|---|---|
| 1. 规则是否明确？ | 有清晰步骤、格式、标准 | 靠感觉、靠品味、主观判断多 |
| 2. 材料是否已备齐？ | 文件/链接/信息都拿到了 | 还要到处找、要问别人 |
| 3. 错误代价多大？ | 最多重做一遍 | 涉及钱、隐私、法律、对外发布 |
| 4. 是否需要实时信息？ | 材料里都有 | 依赖今天发生的新闻/数据 |
| 5. 是否需要你的决策？ | 关键取舍我已想清楚 | 想让 Agent 替我做决定 |
| 6. 结果如何验证？ | 有明确验收标准 | 说不清「什么算做好」 |
| 7. 资料是否敏感？ | 普通文档，可脱敏 | 身份证号、密码、机密文件 |
| 8. 一次还是长期？ | 一次或低频 | 高频重复（学模板/Skill，第四篇） |

判断规则：**第 3、4、5、7 项只要踩到右边，就加人工确认或自己做；其余项越靠左越可放手。**

## 跟着做：评估你的任务

### 第一步：逐项打分

抄下检查表，对序章任务逐项标 ✅（适合）或 ⚠️（要盯）。

### 第二步：定「委派层级」

根据打分给任务定级（第 8 章扩展为完整权限分级表；注意这里的「层级 1–4」说的是**交不交、交多少**，第 8 章的权限分级（L0–L3）说的是**给了什么权限**，两套编号不同，别混用）：

- **层级 1（全自动）**：规则明确、材料齐、风险低 → 可以直接交；
- **层级 2（分段确认）**：中途有不确定 → 每完成一段停一下让你看；
- **层级 3（人工执行关键步）**：涉及决策/敏感操作 → 关键步骤人来做；
- **层级 4（不委派）**：踩了「钱/隐私/法律/实时」红线 → 别碰。

四个层级放一起看：

### 第三步：写下「绝不能让它做的事」

列出禁区，例如：「不能修改 `input` 之外的文件」「不能联网搜索」「不能删除任何原文件」。**禁区要写进任务描述**（第 7 章任务卡的范围与约束字段）。

## 一个完整示例（来自实测）

以第 5 章统一基准任务为例：规则明确（有输出要求清单）✅、材料齐（7 份文件）✅、风险低（可重做）✅、不依赖实时 ✅、不需人决策 ✅、验收标准明确 ✅、可脱敏 ✅ → **判定为层级 1，可全自动**。

实测结果：7 款产品 6/6 交付全部通过（第 6 章选择表），但多款产品自检漏掉了自己的越权读取（Qoder、Hermes 读取了 `input` 外文件）。**结论：层级 1 任务也要做「交付后核验」，尤其核验边界（它到底读了什么、改了什么）。**

## 常见错误与恢复方法

| 现象 | 可能原因 | 怎样修正 |
|---|---|---|
| Agent 编了个假数据，还给了来源 | 幻觉 + 虚构引用 | 涉及数字/来源一律人工核对；要求它标注「已验证」与「推断」 |
| 6 份文件只交了 4 份 | 遗漏 | 验收清单逐项勾；让它先给交付清单再开始 |
| 覆盖了原文件 | 权限开太大 | 用输出到独立目录的约束；重要文件先备份 |
| 读了不该读的文件夹 | 越权（无弹窗也可能发生） | 任务卡写清禁区；交付后检查「它打开过什么」 |
| 自检说全通过，实际有问题 | 自检不可信 | 用验收清单独立核对，不依赖它的自检（第 10 章） |

## 安全提醒

- 涉及**医疗、法律、财务**内容：输出只能作草稿，必须专业人士复核；
- 涉及**发送、发布、购买、删除、付款**：必须人工确认点（第 8 章）；
- 涉及**公司机密、他人数据**：先确认授权，再考虑脱敏；
- 不要在任务描述里粘贴**真实密码、Token、身份证号**。Token（读「托肯」）是 AI 计算文字量的单位，可以理解成「字数」——第 5 章产品页的「按 Token 计费」就是按处理的文字量收费。它不是验证码，也不是银行口令牌。

## 本章小结

1. Agent 擅长规则明确、材料齐备、可验证的重复劳动；
2. 五类风险：幻觉、遗漏、误操作、越权、隐私泄露；
3. 委派按层级：全自动 / 分段确认 / 人工关键步 / 不委派；
4. 自检不可信，交付后必须独立核验；
5. 红线任务（钱/隐私/法律/实时）不委派。
