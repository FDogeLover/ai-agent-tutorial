第 14 章：规则、记忆与个人偏好 ​

本章解决什么问题 ​

Skill 解决「单类任务怎么做」，本章解决「跨任务它该永远知道什么」：你的偏好（用中文回复、格式习惯）、项目的规矩（命名规范、边界）、以及那些「上次说过这次别忘」的事。用不好，它每次像失忆；用过头，一条错误规则会让所有任务持续变糟。产出：个人 Agent 协作约定。

从一个真实场景开始 ​

我在实测中发现一个规律：规则会放大。一款产品只要没有规则约束，就越权读取工作区文件；而一款产品只要自检规则写得太松（「认为全部通过」），就会在多个维度上漏报问题（第 5 章 Qoder 页）。反过来：正确的规则（「自检必须列出实际读取清单」）能让 Agent 的表现稳定变好。

规则是杠杆：一条好规则，杠杆放大正确；一条坏规则，杠杆放大错误。所以「给 Agent 定规则」必须像「给组织定制度」一样谨慎。

先说结论 ​

  1. 两类规则要分清：全局规则（所有任务生效：语言、风格、安全底线）与项目规则（该项目生效：命名、口径、边界）；
  2. 记忆分三层：产品内置记忆（偏好、历史）、项目状态文件（CONTEXT.md，第 11 章）、对话内临时上下文——三层职责不同，别混用；
  3. 记忆要写、要更新、要淘汰：定期检查「这条规则还对吗？这条记忆还准吗？」过时记忆=污染源；
  4. 错误规则放大问题：写规则前先想「这条会不会在特殊场景伤害正确性」；
  5. 协作约定要「书面化 + 可检查」：口头说「你注意点」没用，写成规则文件才生效。

必要概念 ​

  • 全局规则（Global rules）：对该产品所有任务生效的规则（通常在设置的「规则/指令」区）。
  • 项目规则（Project rules）：仅在特定项目生效的规则（通常在项目目录，如 AGENTS.md、CONTEXT.md）。
  • 记忆（Memory）：产品保存的长期信息（偏好、约定、历史要点）。白话解释：Agent 的「长期记忆笔记本」。
  • 淘汰（Eviction）：主动删除过时/错误的记忆。白话解释：定期清理笔记本里划掉的旧页。
  • 放大效应（Amplification）：规则对 Agent 行为的一致性影响——好规则稳定变好，坏规则稳定变坏。

个人 Agent 协作约定（模板） ​

层级内容存放位置
全局安全底线不执行删除/覆盖；不自动发送/发布；不联网搜索未知来源；敏感信息用变量产品的全局规则区
全局风格默认中文；先结论后细节；表格呈现对比；标注「已验证/推断」产品的全局规则区
项目规则命名规范、输出目录、口径、禁区项目根 AGENTS.md 或 CONTEXT.md
项目状态进度、决策、易变信息核验日期CONTEXT.md（第 11 章）
会话临时本次任务的背景、材料入口任务卡（第 7 章）

跟着做：建立并维护你的协作约定 ​

第一步：写「全局安全底线」 ​

用命令式写 3–5 条，覆盖第 8 章高风险动作。示例：

text
- 未经明确许可，不得删除、覆盖或移动任何现有文件；
- 不得执行联网、发送、发布、付款类操作；
- 涉及来源、数字、日期时必须标注「已验证」或「推断」；
- 输出到任务指定的 output 目录，不修改其他位置。

第二步：写「项目规则」 ​

为你的长期项目（序章任务所在项目）写 AGENTS.md 或并入 CONTEXT.md：命名规范、输出位置、口径、禁区。

第三步：检查产品记忆区 ​

找到产品的「记忆/偏好/规则」设置（各产品位置不同，第 5 章界面讲解可参考），确认你写入的规则在正确层级，且没有与项目规则冲突。

第四步：每两周做一次「记忆清理」 ​

检查：哪条规则已过时？哪条记忆已不准？哪条偏好其实你已改变？删除/更新，写进协作约定文件的「变更记录」。

第五步：验证放大方向 ​

用一个小任务测试：加一条规则前后，同一任务的行为是否按预期方向变好？如果没变好甚至变差，回滚规则。

一个完整示例 ​

本书项目的协作约定（实际生效中）：

  • 全局风格规则（写作类）：「先结论后解释；术语首次出现给白话；不堆产品宣传语；区分事实/实测/推断」——这直接来自 docs/03-editorial-guide.md，并落地为章节模板（templates/chapter-template.md）；
  • 全局安全底线：截图脱敏、价格标注核验日期、Claude 封号只写个案；
  • 项目规则（docs/ 系列）：每份文档只负责一个主题、易变信息集中维护（docs/07）、产品页引用而非复制价格；
  • 维护机制：内容清单（docs/04-content-backlog.md）就是「记忆清理」的载体——已完成项打勾，过时项标注。

效果：20 多个章节结构一致、事实口径统一、易变信息集中在 docs/07 一处维护——规则放大了正确。

常见错误与恢复方法 ​

现象可能原因怎样修正
加了规则反而更差规则与场景冲突回滚，加「适用范围」再试
它总忘你的偏好规则放错层级（放对话没放全局）移到全局规则区
记忆里全是过时信息从不清理两周一次记忆清理
项目规则与全局规则打架层级冲突明确「项目规则优先于全局」的说明
规则越加越多，行为僵化过度规则化砍到 80% 场景够用，删极端条款

安全提醒 ​

  • 规则文件会反复被 Agent 读取：绝不写入密钥、账号、身份证号；
  • 全局规则里写死「永远允许/永远禁止」要慎重——用「未经许可禁止 X」而非「禁止 X 一切情况」留出例外空间；
  • 团队/公司环境：项目规则需符合组织政策，规则里不要夹带个人违规约定。

本章练习 ​

30 分钟：完成你的「个人 Agent 协作约定」：全局安全底线 3–5 条 + 项目规则 + 产品记忆区检查 + 一次记忆清理。路线 B 读者重点写「风格偏好」，路线 C/D 读者重点写「安全底线与项目规则」。

你应该带走的成果 ​

  • 个人 Agent 协作约定（全局安全底线 + 项目规则 + 记忆维护机制）。

本章小结 ​

  1. 全局规则管所有任务，项目规则管一个项目；
  2. 记忆分三层：内置记忆、状态文件、临时上下文；
  3. 记忆要写、要更新、要淘汰；
  4. 规则是杠杆，错误规则会放大问题；
  5. 至此第四篇完成：上下文 → 模板 → Skill → 规则记忆，你的「个人工具箱」初具规模。
