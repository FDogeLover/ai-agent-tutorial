WorkBuddy 体验 ​

状态：正文完成；共同基准任务已实测（2026-08-12）

本机版本：5.3.11（运行记录）；界面截图显示 v5.3.12（以最新界面为准）

1. 一句话结论 ​

零基础/中文办公最省心的选择之一：0 人工介入、无需配置模型，成品在客户端内直接 Markdown 渲染，变更统计与逐文件 diff 一目了然（本轮 +647/-0）。实测 5 分 45 秒完成 6/6 交付、消耗 67.25 Credits（本轮托管路径中最高）。注意一处展示不一致：产物列表 6 份但变更列表只显示 5 份，核对时两处都要看。

5. 核心能力 ​

  • 能处理哪些材料：文档、办公材料、多格式文件；统一基准任务中一次生成 6 份 Markdown 成品；
  • 能调用哪些工具：文件系统、任务对话、产物导航、引用来源、变更 diff（本轮用到）；自动化、资料库等入口可见未在本轮触发；

  • 哪些能力实际验证过：共同基准任务完整链路；哪些只来自官方说明：自动化任务、视频生成等扩展入口。

7. 三类实测任务 ​

7.1 共同基准任务（2026-08-12） ​

任务背景 ​

使用冻结的教程材料包（input/ 7 份文件），整理 AI Agent 教程材料，生成六个指定交付文件并自检。

完整输入 ​

冻结材料包 + workbuddy-prompt.md 统一提示。

执行过程 ​

打开 WorkBuddy → 进入「日常办公」→ 选择运行目录 → 保持 Auto 与默认权限 → 粘贴统一提示发送。

最终结果 ​

六份指定文件按顺序生成（07:23:45 首文件至 07:26:43 末文件），总用时 5 分 45 秒（测试者记录；首末文件间隔 2 分 58 秒）。

验收情况 ​

  • 交付：6/6 一次通过，无报错/中断/重试；7/7 输入 SHA-256 与基线一致；
  • 内容亮点：结构化整理、信息缺口识别、新手化目录组织较好；没有编造 Claude 封号原因；
  • 内容偏差：自行生成 21 章目录，把输入包未提供的正式目录/任务/模板当作项目待办——只能作为基准答卷与内容建议，不能覆盖正式 23 章框架；
  • 变更展示：+647/-0、逐文件 diff 清楚；但「查看所有变更」只显示 5 份，漏 06-self-check.md，与 6 份产物列表不一致；
  • 指标：澄清 0 / 权限确认 0 / 人工指导 0 / 恢复 0。

9. 适合与不适合 ​

更适合 ​

  • 零基础、中文办公为主的新手（0 介入、无需配置模型）；
  • 希望「成品看得见、改了什么看得见」的用户（Markdown 渲染 + 行级 diff）；
  • 需要自动化、资料库等扩展能力的办公场景。

可能不适合 ​

  • 对 Credits 消耗敏感的用户（本轮 67.25 Credits 为托管路径最高，需按自身任务量评估）；
  • 需要强代码/Git 工作流的用户（代码能力本轮未验证，建议对照 Qoder/ZCode/Codex）；
  • 追求「交付清单与变更视图完全一致」的严格核对者（存在 6 vs 5 不一致，需人工注意）。

10. 最终结论 ​

  • 是否推荐新手试用：推荐，作为国内综合型首选试用之一；
  • 什么条件下值得购买官方订阅：Free 额度（100 Credits + 新用户 250 + 每日活跃）用完后、日常任务量稳定时考虑 Pro；建议先观察自己单任务的 Credits 消耗再决定；
  • 最适合作为主 Agent、辅助 Agent 还是专用工具：国内办公场景主 Agent 候选；自动化与资料库适合作为长期辅助；
  • 与相邻产品的差异：与 TraeWork 同为国内综合型 0 介入，但 WorkBuddy 的变更可见性（+647/-0 diff）有截图实证，TraeWork 变更环节未验证；成本口径不同（Credits vs 积分）不可横比；
  • 仍需要后续版本继续核验：变更列表遗漏问题的产品修复、自动化/资料库实测、版本 5.3.11→5.3.12 差异、中国区人民币购买路径。
