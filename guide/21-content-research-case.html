第 21 章：内容创作与研究案例——从「一堆经验」到「一套教程」 ​

案例摘要 ​

  • 使用场景：内容创作与研究
  • 使用者基础：能完成第 1–14 章学习即可复现
  • 使用的 Agent：桌面 Agent + 视觉模型辅助（第 5 章界面讲解文档的素材流程）
  • 完成时间：跨周迭代（本书项目本身）
  • 风险等级：低—中（事实可信度管理是重点）
  • 最终交付物：23 章教程框架 + 各章正文（含你正在读的这一章）

任务背景 ​

作者有多款 AI 产品的真实使用经验，想写成一套面向零基础读者的教程。初始问题：经验散落在十几个文档、截图、聊天记录里，不成体系；市面上资料要么是产品说明书，要么是「参数党」评测，缺少「教人怎么用」的实践教程。

原始需求 ​

「我想写一套 AI Agent 教程，把我用这些产品的经验整理出来，教普通人怎么选、怎么用。」

（模糊版：没定读者、没定范围、没定结构——如果直接让 Agent「帮我写教程」，会得到一篇四不像。）

任务判断 ​

  • 为什么适合 Agent：素材整理、框架梳理、长文起草、格式统一；
  • 交给 Agent：素材盘点、目录草案、各章起草、术语统一、易变信息核验辅助；
  • 人必须做的：定读者与边界（零基础、只讲桌面版）、定框架（23 章六篇）、做事实分级（官方事实/实测/推断）、下写作结论。

整理后的任务卡（框架设计阶段） ​

  • 目标：产出教程的完整目录框架与写作规范；
  • 上下文：面向零基础读者；只讲桌面 GUI 版；Qoder/TraeWork/ZCode 只用中国版；
  • 输入材料：作者经验笔记（多份文档）；
  • 范围与约束：不把作者个案写成普遍规律（如 Claude 封号）；易变信息标注核验日期；不虚构引用；
  • 交付物：23 章目录（docs/01-book-outline.md）、编辑规范（docs/03）、内容清单（docs/04）；
  • 验收标准：目录覆盖「认识→选型→任务→工作流→Harness→案例」六篇；每章有明确产出；规范含术语与事实分级要求。

执行过程 ​

  1. 盘点：把经验文档集中到项目目录，用 Agent 帮助提取「可用素材」；
  2. 定框架：人先定六篇叙事线（第 5 篇内容策略），Agent 协助扩展为 23 章；
  3. 定规范：把写作纪律写成 docs/03 编辑规范（先结论、术语白话、事实分级）；
  4. 逐章起草：用章节模板（templates/chapter-template.md）逐章生成——你正在读的每一章都来自这个流程；
  5. 易变信息集中管理：价格/福利统一放 docs/07，各章引用而非复制。

出现的问题 ​

  • 幻觉风险：Agent 起草时出现过「编造价格」「虚构来源」——靠第 10 章事实核查拦截；
  • 范围漂移：初版目录加入了「命令行」「模型原理」内容，违反「零基础、GUI」边界——人修正边界；
  • 事实分级混淆：作者封号经历差点被写成「该产品容易封号」——规范要求写成个案；
  • 版本过期：QoderWork 学生福利已截止仍被当新福利——docs/07 核验清单拦截。

修正与判断 ​

  • 建立「三色事实标注」：官方事实 / 实测结果 / 作者推断，写入 docs/03 并要求每章附录 C 自查；
  • 目录砍掉 CLI 与模型原理内容，移入「选读附录」；
  • 所有价格标注核验日期，活动截止的只作历史信息；
  • 用统一章节模板保证 20+ 章结构一致（第 12 章模板库的价值）。

最终结果与验收 ​

  • 产出：23 章框架 + 编辑规范 + 内容清单 + 第 5、6 章完整正文 + 其余章节正文；
  • 验收：每章过「模板结构」「术语白话」「事实分级」三项检查；链接批量校验（第 18 章回归验证的实践）；
  • 持续迭代：内容清单（docs/04）打勾管理进度，易变信息定期复核。

复盘 ​

  • Agent 做得好的：结构扩展、逐章起草、格式统一、批量校验；
  • 人必须介入的：边界与口径、事实分级、最终结论；
  • 可沉淀：章节模板（templates/chapter-template.md）、编辑规范（docs/03）、易变信息表机制（docs/07）——内容创作类任务的完整方法论。

给新手的最小版本 ​

30 分钟复现：选一个你熟悉的话题（如「如何挑选跑步鞋」）→ 写三条写作纪律（如「价格标日期」「不写没验证的数据」）→ 用任务卡让 Agent 起草一篇带模板结构的短文 → 按纪律验收。内容创作的核心不是「让 AI 写」，而是「定边界、给模板、管事实」。
