第 8 章：在安全边界内让 Agent 行动 ​

本章解决什么问题 ​

前几章让你敢用 Agent 了，这一章教你怎么安全地用。权限是 Agent 使用里最容易被新手忽略、后果却最严重的环节——你以为它只会「读」，它可能「写」；你以为「没弹窗」就是「没动作」，实测证明完全不是。本章产出个人权限分级表，并解释一个反直觉的事实：没有权限弹窗 ≠ 没有越权行为。

从一个真实场景开始 ​

第 5 章实测里，两款产品在任务明确写着「只读 input」的情况下，没有弹出任何权限确认，就读取了工作区其他文件（Qoder、Hermes 页有记录）。另一款产品把文件写进了禁止目录，之后自己恢复（Hermes）。

对新手来说，最危险的错觉是：「它没问我，说明它没乱来。」真相是：权限机制和权限行为是两回事——产品可能默认就允许读取整个工作区，也可能在你没注意时执行了操作。所以你的安全策略不能是「信任弹窗」，而必须是「从最小权限开始，自己控制边界」。

先说结论 ​

  1. 四级权限，逐级开放：只读 → 写入 → 执行 → 外部操作。新手一律从「只读」开始，需要时再升一级；
  2. 逐步开放原则：先在一个临时目录/低风险任务里验证，再对真实文件开放；
  3. 五类动作必须人工确认：发送、发布、付款、删除、提供敏感信息——这些不做成自动步骤；
  4. 备份与可撤销性：让 Agent 动重要文件前，先备份；输出到独立目录，保证「删错了能恢复」；
  5. 权限的最终责任在人：授权是你给的，后果你承担（第 3 章）。

必要概念 ​

  • 只读（Read-only）：能看、能读，不能改。新手最安全的起点。
  • 写入（Write）：能创建/修改文件。只对允许的目录开放。
  • 执行（Execute）：能运行命令/脚本。影响面大，默认关闭。
  • 外部操作（External）：联网、发送消息、调用外部服务、付款等。影响不可逆，最高风险。
  • 可撤销性（Reversibility）：出事后能否恢复原状。白话解释：有没有后悔药。备份、版本记录、独立输出目录都能提供后悔药。
  • 最小权限（Least Privilege）：只给完成当前任务所需的最小权限。白话解释：让实习生只碰他该碰的抽屉。

权限分级表 ​

级别允许什么典型操作风险新手建议
L0 只读读取、分析、总结读文件、查资料、生成建议低从这级开始
L1 写入（限定目录）在指定目录创建/修改文件输出文档、整理素材中输出到独立 output/
L2 执行运行命令/脚本批量重命名、跑脚本、装依赖高默认关闭，看清单再批
L3 外部操作联网、发送、发布、付款发邮件、发帖、下单、删远程极高永远人工确认

你的「个人权限分级表」：为序章任务的每个环节标级别，并写明每一级「允许/禁止」的具体清单。对照第 3 章分工表的「人工确认点」。

跟着做：给你的任务上「权限锁」 ​

第一步：建独立工作目录 ​

为每个任务建独立目录：任务名/input/（只读材料）、任务名/output/（Agent 输出）、任务名/backup/（原文件备份）。让 Agent 只在这三个目录里活动。

第二步：从 L0 开始 ​

第一次跑任务时，只给只读权限：让 Agent 先「读材料、出计划」，你把计划看完，再决定是否升级。

第三步：逐级升级，每次只升一级 ​

计划没问题 → 升 L1（输出到 output/）→ 需要运行脚本 → 升 L2（先看清单）→ 需要联网/发送 → L3 人工做，或每步确认。

第四步：写「权限卡」 ​

在任务卡约束字段基础上，加一张权限卡：

权限项允许禁止
读取input/、材料/其他一切目录
写入output/原文件、input/
执行无（或列出白名单脚本）一切未列出的命令
外部无联网、发送、发布、付款

第五步：验收时检查「它到底碰了什么」 ​

交付后，用产品的变更/历史视图（第 5 章各产品页讲了怎么看）检查：读过的文件清单、写过的文件清单、运行过的操作。第 6 章选择表里的「边界」维度分数，就是各产品在这一步表现的评价。

一个完整示例 ​

以第 5 章统一基准任务的安全设计为例：

  • 目录：runs/2026-08-12-产品名/ 下分 input/、output/、run-record.md；
  • 权限卡：读取=仅 input/；写入=仅 output/；执行=无；外部=无联网；
  • 基线：任务开始前对 input/ 7 份文件记录 SHA-256 哈希（文件指纹），结束后复核「7/7 一致」——这是「可撤销性」的自动检查；
  • 实测结果：多数产品 7/7 一致；Qoder/Hermes 存在读取越界但没有改任何输入文件；Hermes 误写 input/output/ 后自动恢复且哈希仍 7/7——最终状态正确，但过程违规，验收记录里两者分开标注。

这个例子教你：「结果没坏」不等于「过程合规」；权限检查要看过程（读了什么、写了哪），而不只看结果。

常见错误与恢复方法 ​

现象可能原因怎样修正
「它没弹窗，应该没乱来」误以为弹窗=边界验收时检查实际读/写记录（第 10 章）
Agent 改了原文件给了整个目录写入权只给 output/ 写入；原文件先备份
跑了奇怪命令开了 L2 未看清单默认关执行，白名单制
联网乱搜或发了消息外部操作没锁外部一律人工确认
想撤销改错了的文件没备份动手前备份到 backup/；输出用独立目录
权限弹窗看不太懂就点了允许文案不清/赶时间看不懂就拒绝，先查文档再决定

安全提醒 ​

  • 涉及删除、覆盖、格式化：无论 Agent 多「自信」，先备份再让它碰；
  • 涉及支付、发送、发布：永远人工执行最后一步，即使内容 90% 是 Agent 生成的；
  • 涉及公司数据、他人隐私：遵守组织政策，确认授权；
  • 看到不认识的权限弹窗：先拒绝，查清楚再授权；拒绝的成本远低于误授权的成本。

本章练习 ​

25 分钟：为序章任务建目录结构（input/output/backup）、写权限卡（四级允许/禁止清单）、对关键文件做一次备份。如果你已经在用某款产品，找到它的「权限/审批设置」入口，把默认调成最低档。

你应该带走的成果 ​

  • 个人权限分级表（L0–L3 + 允许/禁止清单）+ 任务目录结构 + 备份。

本章小结 ​

  1. 四级权限：只读 → 写入 → 执行 → 外部操作，逐级开放；
  2. 没有弹窗 ≠ 没有越权，验收要看实际读写记录；
  3. 五类动作（发送/发布/付款/删除/敏感信息）永远人工确认；
  4. 备份与独立输出目录提供可撤销性；
  5. 授权在人，后果在人——从最小权限开始。
