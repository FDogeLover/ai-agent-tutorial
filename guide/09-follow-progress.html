第 9 章：跟进过程，而不是只等最终答案 ​

本章解决什么问题 ​

很多新手把任务发给 Agent 后做两件事之一：要么一直刷新等最终答案，要么全程紧张盯屏。两种都错。正确的做法是按风险分阶段监督：知道什么时候该放手、什么时候该叫停、什么时候该插话。本章产出任务过程检查清单，并教你读懂执行过程里真正值得关注的信息。

从一个真实场景开始 ​

我在第 5 章实测里让七款产品做同一个任务，全程观察它们的执行过程：

  • 有的产品把 6 份文件在几秒内一口气写完（快，但你看不见过程）；
  • 有的产品一份一份写，你能在文件系统里看到进度（WorkBuddy、TraeWork 等）；
  • 有一款产品的自检在任务「完成后」又修改了一个文件（Codex 的后置修订）；
  • 有一款产品中途把文件写错位置，自己恢复（Hermes）。

如果你只盯最终答案，以上任何一条你都发现不了。 而「任务是否真的完成、过程是否合规」，恰恰要从过程信息里判断。

先说结论 ​

  1. 监督强度 = 风险函数（呼应第 2 章 L1–L4）：低风险放手跑，高风险分段停；
  2. 三种节奏按需切换：全自动（跑完汇报）、分段确认（每段停一次）、实时接管（高风险/不熟悉任务）；
  3. 过程里真正值得看的四类信息：它在做什么、它遇到了什么问题、它怎么解决的、它有没有越出边界；
  4. 处理四种情况有固定套路：中断→续跑或重跑；追问→补信息；偏航→纠偏并说明；失败→记录原因后重试；
  5. 「Agent 说完成了」是过程信号，不是验收结论——验收是第 10 章的事，这里只管「别让它失控」。

必要概念 ​

  • 分段确认（Checkpoint）：在任务的关键节点暂停，由人确认后再继续。白话解释：装修每做完一阶段，业主验收再进下一阶段。
  • 偏航（Drift）：Agent 的执行偏离了任务目标或约束。白话解释：让它总结 A 材料，它开始扩展成写论文。
  • 过程日志（Log）：Agent 执行动作的记录（读了什么、写了什么、调用了什么）。多数产品有「变更/历史/操作统计」视图（第 5 章各产品页有对照）。
  • 接管（Takeover）：人直接介入纠正 Agent 的当前动作。不要怕接管——及时接管比事后返工便宜。

任务过程检查清单 ​

发任务前（30 秒）：

  • [ ] 任务卡六要素齐全（第 7 章）；
  • [ ] 权限卡已设置、输出目录已建（第 8 章）；
  • [ ] 我已决定监督档位（自动 / 分段 / 接管）。

执行中（按档位检查）：

  • [ ] Agent 是否在按任务卡的目标推进？（不看细节，看方向）
  • [ ] 是否出现了我没授权过的动作？（读/写/联网越界）
  • [ ] 是否卡在同一个问题上反复重试？（>2 次应插话）
  • [ ] 分段确认点是否到了？到了就停下来验收这一段。

执行后（交付前）：

  • [ ] 有没有「后置修改」（它完成后又动了文件）？改了哪、为什么？
  • [ ] 过程日志里有没有越界读写记录？
  • [ ] 有没有把「推测」当成「事实」写进结果？
  • [ ] 交付清单与实际产物是否一致（防止遗漏）？

跟着做：跑一次「带监督」的任务 ​

第一步：定档位 ​

对序章任务，按第 2 章等级定档：L1 全自动、L2 分段、L3/L4 实时接管。

第二步：设分段确认点 ​

如果 L2，明确在哪几处停：通常在「材料读完 → 计划出来」「每完成 1/3 交付物」「自检完成」时。

第三步：执行并记录 ​

用「过程记录表」记下：时间、Agent 在做什么、你做了什么决定：

时间Agent 动作你观察到什么你的决定

第四步：对照检查清单收尾 ​

交付前过一遍「执行后」的四项检查，把异常写进记录，留到第 10 章验收。

一个完整示例 ​

我实测 Codex 时的过程观察（详见第 5 章 Codex 页）：

  • 任务：统一基准（材料整理，L1 低风险）→ 监督档位设为「全自动 + 交付后检查」；
  • 执行：6 份文件几乎同时写入 → 视为正常；
  • 异常信号：约 1 分钟后 02-information-gaps.md 被再次修改（后置修订）——我没有打断，记下「最终版本按后置版本验收」；
  • 交付后检查：自检覆盖 7 份输入、无越界记录 → 通过；
  • 结论：全自动档位 + 交付后检查，适用于 L1；那个后置修订如果不看过程就发现不了，也就无法决定「按哪个版本验收」。

常见错误与恢复方法 ​

现象可能原因怎样修正
一直刷新等最终答案把过程当黑箱看「它在做什么」的过程信息；L2+ 设分段确认
全程盯屏不敢离开监督过度低风险段设「跑完汇报」，别事无巨细
Agent 卡住反复重试缺信息/指令矛盾插话补信息或澄清，别让它空转
它跑偏了才发现没设分段点关键节点设确认点
任务「完成」后又变了文件后置修改记录并决定验收版本，别只看首次完成时间
看不懂过程信息界面不熟用第 5 章各产品页的「过程/变更视图」说明对照学习

安全提醒 ​

  • 看到权限弹窗、联网请求、执行命令时，即使任务快完成了，也要停下来确认——「快跑完了」不是忽略风险的理由；
  • Agent 反复重试同一操作时，先怀疑「方向错了」，不要让它无限重试；
  • 对外动作（发送/发布）即使 Agent 说「已准备好」，也要你亲手完成最后一步。

本章练习 ​

20 分钟：用「过程记录表」重跑你上一个真实任务（或序章任务），按检查清单过一遍，找出 2 个你以前忽略的过程信号。

你应该带走的成果 ​

  • 任务过程检查清单（发前/执行中/交付后三组）+ 过程记录表。

本章小结 ​

  1. 监督强度随风险变化：自动 / 分段 / 接管三档；
  2. 过程里看四件事：在做什么、遇到什么、怎么解决、有没有越界；
  3. 中断/追问/偏航/失败各有固定处理套路；
  4. 「完成」是过程信号，不是验收结论；
  5. 后置修改、越界读写这些信号，只有跟进过程才看得到。
