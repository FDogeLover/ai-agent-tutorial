第 2 章：Agent 能做什么，不能做什么 ​

本章解决什么问题 ​

很多人第一次用 Agent 只有两种体验：要么惊艳（「它居然全会！」），要么翻车（「它居然敢这么干！」）。这两种体验都源于同一个问题——不知道 Agent 的能力边界在哪里。本章给你一张任务适配性检查表：什么任务放心交给它、什么任务要加人工确认、什么任务根本不该碰。

从一个真实场景开始 ​

我测试一款 Agent 时，任务明确写着「只允许读取 input 文件夹的材料」。它正常完成了任务、没有任何报错，自检还写着「全部通过」。但事后检查产物时发现：它悄悄读取了工作目录之外的文件（第 5 章 Qoder 页有完整记录）。

同一批测试里，另一款 Agent 把文件写错了位置（写进了只读目录），然后自己发现、自己迁移、自己复核（第 5 章 Hermes 页）。

这两个案例说明两件事：Agent 可能在你没注意时越界；Agent 也可能在出事后自我修复。「能生成结果」和「结果可信」是两件事——这正是本章要训练你的判断力。

先说结论 ​

  1. Agent 擅长：信息密集的重复劳动、多步骤的文档/数据整理、需要工具调用的执行类任务、可以在材料范围内自查的任务；
  2. Agent 不擅长：需要实时现实感知的事（它不知道今天天气变了）、需要价值取舍的事（它替你决定「哪个更重要」很危险）、需要它为自己的话负责的事；
  3. 五类风险要盯住：幻觉（编造）、遗漏（漏做）、误操作（改错）、越权（碰了不该碰的）、隐私泄露（资料外流）；
  4. 最反直觉的一条：Agent 越「自信」地声称完成了，越要核对——自检通过 ≠ 真的通过。实测中多款产品的自检都漏掉了自己的问题。

必要概念 ​

  • 幻觉（Hallucination）：AI 生成了看起来合理、实际错误的内容。白话解释：它在「一本正经地胡说八道」。原因：它生成的是「最像样的答案」，不是「经过验证的事实」。
  • 遗漏（Omission）：任务有多个部分，它只做了一部分，且可能不告诉你。白话解释：老师布置 6 道题，它做了 4 道就说「写完了」。
  • 误操作（Misoperation）：执行时改了不该改的文件、删了不该删的内容。白话解释：让实习生整理文件夹，他把你的原稿覆盖了。
  • 越权（Overreach）：行为超出你授予的范围（读取范围、写入范围、联网、调用外部服务）。
  • 自检（Self-check）：Agent 在交付前对结果做的自我检查。注意：自检是 Agent 的产品设计，不是可信保证——实测里自检漏报是常态。

任务适配性检查表 ​

把序章的任务种子拿出来，逐条勾选：

检查项越符合 → 越适合交给 Agent越符合 → 越要人盯/别碰
1. 规则是否明确？有清晰步骤、格式、标准靠感觉、靠品味、主观判断多
2. 材料是否已备齐？文件/链接/信息都拿到了还需要到处找、要问别人
3. 错误代价多大？最多重做一遍涉及钱、隐私、法律、对外发布
4. 是否需要实时信息？材料里都有，不依赖实时依赖今天发生的新闻/数据
5. 是否需要你的决策？关键取舍我已想清楚想让 Agent 替我做决定
6. 结果如何验证？有明确验收标准（数量、格式、事实）说不清「什么算做好」
7. 资料是否敏感？普通文档，可脱敏身份证号、密码、机密文件
8. 一次还是长期？一次或低频高频重复（建议学模板/Skill，见第四篇）

判断规则：第 3、4、5、7 项只要有一项踩到右边，就加人工确认或干脆自己做；其余项越靠左，越可以放手。

跟着做：评估你的任务 ​

第一步：逐项打分 ​

把「任务适配性检查表」抄下来，对序章任务逐项标 ✅（适合）或 ⚠️（要盯）。

第二步：定「委派等级」 ​

根据打分给任务定级（第 8 章会扩展成完整的权限分级表）：

  • L1 全自动：规则明确、材料齐、风险低 → 可以直接交；
  • L2 分段确认：中途有不确定 → 每完成一段停一下让你看；
  • L3 人工执行关键步：涉及决策/敏感操作 → 关键步骤人来做；
  • L4 不委派：踩了「钱/隐私/法律/实时」红线 → 别碰。

第三步：写下「绝不能让它做的事」 ​

白纸黑字列出这个任务的禁区，例如：「不能修改 input 之外的文件」「不能联网搜索」「不能删除任何原文件」。禁区要写进任务描述（第 7 章任务卡的范围与约束字段）。

一个完整示例（来自实测） ​

以本书第 5 章的统一基准任务为例，看检查表如何用：

  • 任务：整理 7 份教程材料，生成 6 份指定文档（总结/缺口/目录/计划/待办/自检）；
  • 检查表：规则明确（有输出要求清单）✅；材料齐（7 份文件）✅；风险低（可重做）✅；不依赖实时 ✅；不需要人做决策（材料范围内整理）✅；验收标准明确（6 份 + 哈希一致）✅；资料可脱敏 ✅ → 判定 L1，可全自动；
  • 实测结果：7 款产品 6/6 交付全部通过（第 6 章选择表），但——多款产品自检漏掉了自己的越权读取（Qoder、Hermes 读取了 input 外文件）、自检称「全部通过」实际有遗漏（Qoder）。结论：L1 任务也要做「交付后核验」，尤其核验边界（它到底读了什么、改了什么）。

常见错误与恢复方法 ​

现象可能原因怎样修正
Agent 编了个假数据，还给了来源幻觉 + 虚构引用涉及数字/来源一律人工核对；要求它标注「已验证」与「推断」
6 份文件只交了 4 份遗漏验收清单逐项勾；让它先给交付清单再开始
覆盖了原文件权限开太大 / 没约束用输出到独立目录的约束；重要文件先备份
读了不该读的文件夹越权（无弹窗也可能发生）任务卡写清禁区；交付后检查「它打开过什么」
自检说全通过，实际有问题自检不可信用验收清单独立核对，不依赖它的自检（第 10 章）

安全提醒 ​

  • 涉及医疗、法律、财务内容：Agent 输出只能作草稿，必须专业人士复核；
  • 涉及发送、发布、购买、删除、付款：必须人工确认点（第 8 章）；
  • 涉及公司机密、他人数据：先确认授权，再考虑脱敏；
  • 不要在任务描述里粘贴真实密码、Token、身份证号。

本章练习 ​

20 分钟：用「任务适配性检查表」给序章任务定级（L1–L4），写下三条「绝不能让它做的事」。如果你是路线 C/D 读者，再找一个曾经翻车的旧任务，用它跑一遍检查表，找出当初漏了哪一项。

你应该带走的成果 ​

  • 任务适配性检查表（8 项判定 + 委派等级 L1–L4 + 三条禁区）。

本章小结 ​

  1. Agent 擅长规则明确、材料齐备、可验证的重复劳动；
  2. 五类风险：幻觉、遗漏、误操作、越权、隐私；
  3. 「能生成结果」≠「结果可信」，自检通过 ≠ 真的通过；
  4. 用检查表给任务定级（L1–L4），红线任务不委派；
  5. 禁区必须写进任务描述，交付后独立核验边界。
