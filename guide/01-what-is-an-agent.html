第 1 章：AI Agent 到底是什么 ​

本章解决什么问题 ​

你天天听人说「AI Agent」，但可能说不清它和 ChatGPT 聊天框有什么区别。本章用一个贯穿全书的生活化比喻，把五个核心概念（模型、上下文、工具、记忆、权限）讲清楚，并让你画出一张Agent 工作流程图。看完后你会明白：为什么「会聊天」不等于「会干活」，以及桌面 Agent 里那个「自动完成任务」的按钮背后发生了什么。

从一个真实场景开始 ​

你让聊天 AI「帮我整理一下旅行照片」。它回复：「好的！你可以先按日期分类，再删除模糊的……祝旅途愉快！」——它给了你一篇攻略，但照片一张都没动。

同样一句话，如果你对桌面 Agent 说，它可能：打开你的照片文件夹 → 按日期和地点分组 → 把重复照片挑出来放到「待删除」文件夹 → 生成一份带说明的相册目录 → 告诉你「共整理 214 张，重复 37 张，说明文件在 output 目录下」。

两者都能「回答」，只有后者「干活」。 这中间的差别，就是本章要讲的东西。

先说结论 ​

  1. Agent 的本质是「能执行任务的 AI」，聊天 AI 的本质是「能生成回答的 AI」——执行意味着它要自己规划步骤、调用工具、读写文件，并对结果负责；
  2. Agent 由五块拼图组成：模型（思考的脑子）、上下文（眼前能看到什么）、工具（能动手做什么）、记忆（长期记得什么）、权限（被允许做什么）；
  3. 模型能力不是 Agent 的全部：同样的模型放在不同的 Agent 里，体验可能完全不同——因为工具、权限和验证流程是产品自己搭的（第 5 章实测会反复证明这一点）；
  4. Agent 也会犯错，而且犯错的形态和聊天 AI 不同：它可能读错文件、改错地方、或者「自信地」做了一件你没让它做的事。知道它由什么组成，你才知道该检查哪里（第 2、8、10 章展开）。

必要概念（用一个比喻） ​

把 Agent 想象成一位新入职的实习生。它有五个属性：

概念白话解释实习生比喻
模型Agent 用来思考和生成内容的 AI 大脑实习生的「能力水平」——学历和智商
上下文这次任务里它能「看到」的全部信息：你的话、文件、规则实习生眼前摊开的资料和你的口头交代
工具它实际能调用的能力：读文件、写文件、跑计算、访问网页实习生能用的电脑、打印机、电话
记忆跨任务记住的长期信息：你的偏好、历史约定实习生的笔记本和你的口头约定
权限它被允许做的事的范围：哪些文件夹能碰、哪些操作要请示实习生的门禁卡和「需要经理审批」的规定
  • 模型：白话解释「一个根据你输入的内容，预测并生成下一步文字的巨型程序」。正式说法：通过大规模训练学会理解和生成自然语言等内容的神经网络。它决定 Agent「想得到想不到」，但不决定它「做得到做不到」。
  • 上下文：本次任务 Agent 能看到的全部信息总和。它不能像人一样「凭记忆」——没放进上下文的信息，对它等于不存在。
  • 工具：Agent 主动调用的外部能力（文件读写、命令行、浏览器、表格）。有工具的 Agent 才能从「说话」变成「干活」。
  • 记忆：产品提供的长期存储（规则、偏好、历史）。很多产品把「记忆」做成可编辑的文件或设置项。
  • 权限：产品对 Agent 行为的限制规则。它决定 Agent 能否写文件、能否联网、哪些操作需要你点击确认。

三种形态，三个台阶 ​

形态例子会做什么不会做什么
聊天 AIChatGPT 网页聊天生成回答、写文案、问答自己动你的文件、替你执行
Copilot（副驾驶）编辑器里的补全助手在你操作时给建议、补全当前内容独立完成多步骤任务
Agent（智能体）桌面 Agent（本书第 5 章七款）接收任务、规划、调用工具、交付结果替你承担最终责任（责任仍在人，第 3 章）

理解台阶的意义：不是越高级越好，而是匹配任务。查一个事实用聊天 AI 最快；写代码时 Copilot 顺手；而「把一摊材料整理成六个文档」这种多步骤任务，才值得动用 Agent。

跟着做：画一张 Agent 工作流程图 ​

以你序章写下的「任务种子」为例子，画出 Agent 处理它的过程：

第一步：画出「人 → Agent」的输入 ​

人（你）做什么：定目标、给材料、定约束、定验收标准。在纸上左侧画一个人形，箭头指向右侧的「Agent」，箭头旁写下：目标、材料、约束。

第二步：画出 Agent 内部的三段循环 ​

在纸中间画一个大框（Agent），里面画三段循环：

  1. 理解：读目标 + 读上下文（材料、规则）；
  2. 行动：调工具（读文件、生成内容、写文件）；
  3. 反馈：观察结果，决定继续、修正或结束。

用循环箭头把三段连起来：理解 → 行动 → 反馈 →（回到）理解。

第三步：画出「Agent → 人」的交付与检查 ​

右侧再画一个人形（还是你），从 Agent 框画出输出箭头：成品、过程记录、自检说明。在旁边写一句：「我检查，我负责」。

第四步：对照你用的产品，找这五块在哪 ​

打开你已经装好的任一桌面 Agent（没有就先跳过，第 4 章会选），试着找：

  • 模型/模式：通常在设置或对话上方（如「Auto」「默认模型」）；
  • 上下文：对话里引用文件（@文件）、任务描述、项目目录；
  • 工具：任务面板里出现的「读文件」「写文件」「搜索」等动作；
  • 记忆：产品里的「规则」「偏好」「项目配置」；
  • 权限：设置里的「权限模式」「需要确认的操作」。

一个完整示例 ​

用我实测过的场景（第 5 章 WorkBuddy 体验页有完整记录）走一遍流程图：

  • 输入：任务「整理 AI Agent 教程材料，生成六份指定文档」+ 材料包（7 个文件）+ 约束（只读 input 目录、输出到 output）+ 验收标准（6 份文件齐全、输入哈希一致）；
  • 理解：Agent 读取材料包与任务说明，规划步骤；
  • 行动：读取 7 份材料 → 逐份生成 6 份文档 → 写入 output → 运行自检；
  • 反馈：自检发现材料边界偏差（把裁剪输入外内容列为缺失）→ 停止并在自检中说明；
  • 交付：6 份文档 + 自检说明；人复核后发现「产物列表 6 份但变更列表只显示 5 份」的展示问题，以文件系统为准验收。

这个例子说明：流程图每一步都可能出问题，而检查点（反馈 → 人复核）才是流程能闭环的关键。

常见错误与恢复方法 ​

现象可能原因怎样修正
以为模型强 = Agent 好用把模型能力等同于产品能力对照第 5 章：同样的 DeepSeek V4 Flash，不同产品体验不同
把聊天 AI 的对话习惯用在 Agent 上没意识到 Agent 会「动手」先想清楚：这次任务要不要它碰我的文件？
找不到「记忆」在哪里产品术语不同（规则/偏好/项目配置）看产品文档，或直接问它的帮助入口
画流程图时发现「权限」没概念还没用过会写文件的 Agent先读第 8 章再回来画

安全提醒 ​

  • 让 Agent 动手的第一原则：先给只读权限或临时目录，确认它能正确理解范围后再逐步放开（第 8 章系统讲解）；
  • 你的「任务种子」暂时不要包含账号密码、身份证号等敏感信息。

本章练习 ​

15 分钟：按「跟着做」四步画出你的 Agent 工作流程图；如果你已经装了某款桌面 Agent，找出它的五块拼图分别在界面的哪里，标注在图上。

你应该带走的成果 ​

  • 一张 Agent 工作流程图（可以手画或画在文档里），标注出你所用产品的五块拼图位置。

本章小结 ​

  1. Agent 与聊天 AI 的根本区别：执行任务，而不只是生成回答；
  2. Agent = 模型 + 上下文 + 工具 + 记忆 + 权限；
  3. 聊天 / Copilot / Agent 是三个台阶，匹配任务才重要；
  4. Agent 的工作是「理解 → 行动 → 反馈」的循环；
  5. 反馈与人的检查，才是流程闭环的关键。
