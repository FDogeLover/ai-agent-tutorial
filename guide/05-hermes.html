Hermes Desktop 体验 ​

状态：正文完成；共同基准任务已实测（2026-08-12）

本机版本：桌面应用 0.17.0（可执行文件版本 40.10.2 是 Electron 版本，不是产品版本）

最后本机核对：2026-08-12；订阅核验：2026-08-11

1. 一句话结论 ​

高自主、模型自由、自托管型 Agent 的代表：预览/源码/差异/编辑四视图最灵活，也是本轮唯一触发并自动恢复真实路径错误的样本（误写 → 自动迁移 → 删除误建目录 → 哈希复核，全程无需人工）。「极客属性」来自模型接入、配置自由度与维护责任，而非界面简陋——GUI 本身成熟易用。适合有系统配置经验的读者，不适合零基础。

3. 下载、安装与首次启动 ​

  • 下载和安装：官方发布页下载 Windows 安装包，安装顺利（本机安装于 %LOCALAPPDATA%\hermes\hermes-agent）；
  • 是否必须注册、登录或绑定其他服务：应用不需要；首次使用需配置 Provider（API Key/Endpoint）与模型——这是新手的主要门槛；
  • 首次权限提示：可配置权限/审批模式；本轮为「智能审批」，未触发人工确认弹窗；
  • 主界面导航：成熟三栏工作台——左侧新建会话、技能与工具、消息平台、产物、项目和 Profiles；中间会话、分支、上下文、模型选择；右侧项目文件树和终端；顶部布局编辑器、HUD 模式和侧栏控制；
  • 新手从启动到完成第一个任务：新建 Project → 选择运行目录 → 配置 Provider 与模型 → 粘贴提示词 → 发送（需先跨过 Provider 配置）；
  • 是否有只能通过 CLI/TUI 才能完成的重要能力：官方另有 CLI/Agent 形态；本页只评价 Desktop，未发现桌面端缺失本轮必需能力。

5. 核心能力 ​

  • 能处理哪些材料：文档、代码、项目文件；统一基准任务中一次生成 6 份 Markdown；
  • 能调用哪些工具：文件系统、消息平台、技能与工具、项目文件树、终端、多视图预览（本轮用到文件写入与恢复）；自动化与长期项目能力入口可见；
  • 代表性功能：四视图切换（预览/源码/差异/编辑）、自动恢复、Provider 多供应商接入、Profiles；
  • 哪些能力实际验证过：共同基准任务完整链路 + 一次自动恢复；哪些只来自官方说明：消息平台集成、自动化深度能力。

6. 界面与工作方式 ​

  • 运行位置：本地桌面应用（模型经外部 Provider）；
  • 用户如何观察和控制执行过程：中间对话流看任务说明与结论，右侧文件树看产物，差异页可看预览/源码/差异/编辑四种形态。
维度观察记录适用前提

7. 三类实测任务 ​

7.1 共同基准任务（2026-08-12） ​

任务背景 ​

使用冻结的教程材料包（input/ 7 份文件），整理 AI Agent 教程材料，生成六个指定交付文件并自检。

完整输入 ​

冻结材料包 + hermes-prompt.md 统一提示。

执行过程 ​

打开 Hermes Desktop → 新建独立 Project 并选择运行目录 → 使用当前已配置 Provider 与模型（不显示/修改密钥）→ 保持默认推理、权限与工具设置 → 粘贴统一提示发送。

最终结果 ​

约 5–7 分钟完成（测试者记录；首批产物到最后产物写入间隔 1 分 25 秒）。过程中发生一次自动恢复：因当前目录位于 input，前两份文件被相对路径误写入 input/output/，随后 Agent 自行迁移到根 output/、删除误建目录并复核输入哈希。

验收情况 ​

  • 交付：6/6 最终完成，内容详细；7/7 输入 SHA-256 与基线一致；误建目录已清理；
  • 内容亮点：自检诚实披露路径偏差与修复过程（透明度较高）；信息缺口 A-E 分类完整；
  • 内容偏差：自行压缩为第 0–7 章目录，只能作为基准答卷不能替换正式 23 章框架；把「误写后清理」仍评为权限边界全部遵守，结论过宽；读取了 input 之外的项目文件；
  • 指标：澄清 0 / 权限确认 0 / 人工回复 0 / 依赖安装 0 / 中断 0 / 报错 0 / 人工重试 0 / 内部路径偏差 1 / 自动恢复 1。

本轮已实际触发一次边界场景（路径误写 + 自动恢复），是七款中唯一的真实恢复案例；更广泛的边界（Provider 不可用、上下文过长、权限拒绝）待 benchmark v2 补测。

8. 遇到的问题与恢复 ​

问题出现条件对结果的影响恢复步骤新手能否独立处理
相对路径误写到输入目录执行时当前目录位于 input，使用相对 output/...临时在输入树内创建 input/output/ 并写入两份产物，违反写入边界自动迁移到根 output/、删除误建目录、复核 7/7 哈希用户侧无提示；若未自检可能难以发现
读取范围越过 inputAgent 可读取整个 Project自检引用根目录运行文件验收标注范围偏差，不采信自检「全部遵守」智能审批未弹窗不代表严格限制读取
成本不可见使用外部 Provider/API无法换算本轮成本记录未知，不估算新手需自行理解供应商计费与余额

教学价值：Hermes 的误写恢复案例是教程「Harness/权限/恢复」章节的绝佳素材——它清楚演示了「最终正确 ≠ 过程合规」，安全、恢复、透明度应分开评价。

9. 适合与不适合 ​

更适合 ​

  • 重视模型自由、多供应商接入的自托管用户；
  • 需要高自主、长期自动化任务的用户；
  • 愿意承担环境配置与维护责任的读者（四视图核对体验好，配置门槛可接受）。

可能不适合 ​

  • 零基础新手（Provider/模型/环境概念门槛高）；
  • 不想管理 API Key 与外部账单的用户（成本不可见）；
  • 对数据边界有严格要求且不希望「无弹窗越权读取」的用户（本轮存在边界失分）。

10. 最终结论 ​

  • 是否推荐新手试用：不优先推荐——先通过教程第 2 章理解模型/API 概念，再在熟悉环境后试用；
  • 什么条件下值得购买官方订阅：按需购买 Portal 月度 Credits 或使用自有 API；应用本身开源免费；
  • 最适合作为主 Agent、辅助 Agent 还是专用工具：自托管型主 Agent 候选；高自主任务与自动化场景价值最大；
  • 与相邻产品的差异：与 ZCode 同属 BYOK 路径，Hermes 恢复能力唯一实证（自动恢复），ZCode 变更统计更细；与托管路径（Codex/WorkBuddy 等）相比，Hermes 配置自由度最高、但开箱即用性最低；
  • 仍需要后续版本继续核验：Provider 不可用时的恢复、消息平台集成、长期自动化稳定性、精确成本核算。
