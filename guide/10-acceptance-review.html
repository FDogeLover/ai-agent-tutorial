第 10 章：验收、纠错与复盘 ​

本章解决什么问题 ​

任务跑完了，Agent 说「已完成」。然后呢？验收是人与 Agent 协作里最关键、也最被新手跳过的一步。 本章教你四类验收方法、如何区分「表达不好」和「任务失败」、如何用验收反馈推动修正，以及如何从一次任务里沉淀下次可复用的经验。产出：任务验收与复盘记录。

从一个真实场景开始 ​

第 5 章实测里，一款产品的自检写着「25 项全部通过」，但实际检查发现：待办清单全部未勾选、读取范围越过了 input、连一个临时文件都没发现（Qoder 页）。另一款产品的自检诚实披露了自己写错路径又恢复的过程（Hermes 页）。

如果你把「自检通过」当成验收，第一款的严重问题你永远不会发现。 验收必须独立于 Agent 的自检——用你自己的清单，逐项打勾。

先说结论 ​

  1. 四类验收：事实核查（对不对）、计算复核（算不算得对）、文件检查（全不全、格式对不对）、实际测试（能不能用）；
  2. 区分两种失败：「表达不好」（措辞、结构问题，改改就行）vs「任务失败」（目标没达成、事实错误、边界违规，要重做）——处理方式完全不同；
  3. 验收反馈要具体：「第二页的数据错了，来源是材料 X，请改为 Y」比「你做得不对」有效百倍；
  4. 复盘沉淀三样东西：模板/清单更新、Skill 候选、Harness 改进点（为第四、五篇铺路）；
  5. 可验收的才是可委派的：第 7 章任务卡的验收标准字段，在这里兑现。

必要概念 ​

  • 事实核查（Fact check）：核对输出中的事实、数字、来源是否真实准确。Agent 可能幻觉（第 2 章），所以数字和来源必须查。
  • 文件检查（File check）：核对交付物是否存在、数量是否齐全、格式是否符合要求、位置是否正确。
  • 实际测试（Actual test）：让交付物在真实场景里跑一遍（打开文档、运行脚本、试用界面）。
  • 复盘（Retrospective）：任务结束后回顾「哪些做得好、哪些浪费了、下次怎么改进」。白话解释：打完仗开个总结会。

验收清单（四类） ​

类别检查项怎么查
事实数字/日期/来源是否真实对照原始材料；可疑处单独核对
事实是否区分「已验证」与「推测」看输出有没有标注
计算统计、合计、比例是否算对抽查重算；用表格工具复核
文件交付物数量与名称对照任务卡交付物清单逐项勾
文件格式/结构是否符合要求打开检查标题层级、表格、命名
文件是否落在指定目录检查 output/ 目录
边界是否只读了允许范围看过程日志/变更记录（第 9 章）
测试文档能否打开渲染实际打开
测试表格/清单能否直接使用实际操作一遍

跟着做：完成一次验收与复盘 ​

第一步：对照验收标准逐项打勾 ​

把任务卡的验收标准拿出来，逐项检查，不要看 Agent 的自检结论，只看实际产物。每项标 ✅ / ❌ / ⚠️。

第二步：区分失败类型 ​

  • 表达不好（改改就行）：措辞生硬、结构乱、示例不合适 → 让 Agent 修改，不改目标；
  • 任务失败（要重做/部分重做）：事实错误、漏交付、越界、格式完全不符 → 修正任务卡后重跑，或人工修补。

第三步：写具体的修正反馈 ​

格式：位置 + 问题 + 期望。例：「02-information-gaps.md 第 3 节把 D-05 标成了『事实』，但材料里没有来源，请改为『推断』并加说明。」

第四步：复核修正结果 ​

Agent 改完后，只检查修正点（避免被带着走），确认后再验收。

第五步：写复盘记录 ​

复盘项记录
Agent 做得好/差的地方
人必须介入的地方
下次可省略或自动化的步骤
可沉淀的模板/Skill/Harness 组件
任务卡/权限卡的改进点

一个完整示例（验收记录节选） ​

以第 5 章统一基准任务的验收为例（完整验收在 research/runs/*/run-record.md）：

  • 任务：6 份交付物 + 自检（L1）；
  • 验收：6/6 文件存在 ✅；输入哈希 7/7 与基线一致 ✅（文件检查）；内容对照材料抽查 ✅；边界检查 ❌——读取范围记录显示越过了 input（Qoder/Hermes）；
  • 失败类型判断：交付物内容合格，但边界违规属于「部分任务失败」（过程不合规）；
  • 修正反馈：不需要重做产物，但验收记录中单独标注「过程越界」，并在教程中提示该产品「效率与边界分开评价」；
  • 复盘沉淀：①验收清单新增「边界检查」项（看读取记录，不只看结果）；②各产品的边界表现成为第 6 章选择表「边界」维度的数据来源；③「无弹窗 ≠ 合规」成为第 8 章的安全原则。

这个例子说明：验收不是「打勾通过」，而是把发现的问题变成规则和资产。

常见错误与恢复方法 ​

现象可能原因怎样修正
把自检当验收图省事用独立清单逐项查，自检仅供参考
「感觉不对但说不出哪不对」没按清单查按四类清单逐项过，问题会自己浮出来
修正后整体重查一遍浪费且易被带偏只查修正点
数据错了没发现事实核查缺失涉及数字一律对照来源
复盘就是「下次注意」太虚落到「更新哪个清单/模板」的具体动作

安全提醒 ​

  • 涉及财务、医疗、法律的输出：验收时必须有专业复核，四类验收只是基础；
  • 涉及对外发布：验收合格 ≠ 可以发布，发布动作永远人工执行；
  • 验收时发现敏感数据泄漏（如产物里出现账号信息），立即删除并修改任务卡约束。

本章练习 ​

30 分钟：用验收清单验收你上一个真实任务的交付物（或重跑序章任务），完成一份「任务验收与复盘记录」。重点：找到至少 1 个 Agent 自检没发现的问题，并把它变成一条可复用的检查项。

你应该带走的成果 ​

  • 任务验收与复盘记录（四类验收结果 + 失败类型 + 修正反馈 + 复盘沉淀）。

本章小结 ​

  1. 验收独立于自检：事实、计算、文件、测试四类；
  2. 「表达不好」改改就行，「任务失败」要重做；
  3. 修正反馈要具体：位置 + 问题 + 期望；
  4. 复盘把经验变成清单、模板与 Skill 候选；
  5. 至此你已走通「任务卡 → 安全边界 → 过程跟进 → 验收复盘」的完整闭环（第三篇完成）。
